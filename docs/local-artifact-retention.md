# 本机构建产物保留

本地打包和验收结束后，应整理过期产物，不持续累积每轮安装包和构建副本。

- 对外提供的安装包保留最新两个版本；`NoteBoard-current-setup.exe` 作为当前版本入口，合计最多三个文件。按实际构建时间和内容校验判断新旧，同一版本号下的修复包也算不同构建。
- NSIS 构建历史最多保留最近两份。过期临时安装包、应用基线副本和隔离 QA 配置应一并整理；隔离 QA 配置最多保留最近两份。
- Cargo 编译缓存和构建历史分开处理。保留当前 release 缓存以免每次打包重新编译依赖；长期不用的 debug 缓存、旧增量缓存和参考项目的 target 可以重新生成，应按占用清理。
- 源码、Git 历史、锁文件、依赖、压测文档、测试证据和原用户数据备份不属于待清理的构建历史。不能用扩展名或目录大小单独判断可删范围。

执行清理前应确认完整绝对路径、实际卷、所有祖先目录和内容中的 junction / symlink，禁止跨链接递归处理。只处理本项目确认的生成物；共享 Cargo、pnpm 和系统临时目录不能当作本项目私有缓存。

当前本机工作区位于 C 盘。不得通过清理本项目移动或删除 D 盘内容。Windows 登录 shell 可能把 `TEMP` / `TMP` 改成 `D:\msys64\tmp`；后续本项目命令应使用干净 shell，核对临时目录仍在 C 盘，必要时仅对子进程指定项目内临时目录，不修改用户级环境配置。

本轮采用可恢复的集中整理：先生成精确清单并核对保留产物哈希，再将每个确认的过期文件或目录逐项移动到工作区根的 `待删除-NoteBoard-构建缓存-<时间>`。不执行批量删除，不绕过工具的拒绝。待删除目录附原路径清单，用户可以在资源管理器中手动删除整个目录。仅同卷移动不释放空间，删除该目录后才释放 C 盘空间。
