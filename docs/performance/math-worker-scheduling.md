# 公式 worker 的有界调度

`renderMath(latex, displayMode, options)` 保持原有接口。调用方可以同时准备多条公式；调度器在同一轮微任务末尾选取当前最高优先级的一批请求，避免每条短公式都等待一次 `setTimeout(0)` 和 worker 请求往返。DOM 挂载、视口保留和导出布局仍由各自模块负责。

## 边界与协议

- 每批最多 16 条、源码合计最多 8192 个 UTF-16 单元。超过批次源码预算但仍通过单式准入的公式独占一批；单式 16384 字符上限保持不变。
- worker 顺序计算，完成单式后检查 8 ms 软时间预算。耗尽预算立即结束本批，未开始的尾部回到主线程重新竞争优先级。单式本身无法在 KaTeX 同步运算中协作中断。
- 同一批只包含派发时优先级相同的请求，每个批次结束重新读取消费者的动态优先级。新可见工作最多等待当前短批次，或其中正在执行的受硬超时约束的单式。
- 一个请求消息可以派发多式；每条完成结果直接流回，不等待主线程确认。批次结束标记附在最后一条结果上。保留逐式结果是为了在后续单式卡住时留下已完成结果，并识别真正未完成的首项。
- 每批只建立一次 watchdog，收到结果仅更新时间戳。距本批派发或上一条完成消息达到 2 秒仍无进展时，终止 worker、将首个未完成式报告为超时，未开始尾部重新排队。watchdog 若被已有进展延期，只在到期检查时重设，不为每条短公式建立新定时器。
- 取消只移除该消费者。派发前没有消费者的任务不会启动；已派发的小批次可以继续计算并预热缓存，切片结束时未执行且已无人订阅的尾部直接删除。共享请求、重新进入视口以及独立导出消费者保持隔离。
- 结果缓存仍同时受 512 项与 4 MiB 估算字节预算约束；一般渲染错误和超时不缓存，确定的准入拒绝可以缓存。源码、输出长度和节点数准入保持不变。
- 没有 Worker 的测试/SSR 回退每个切片之间让出一次事件循环；此回退不能硬中断同步 KaTeX。浏览器使用可终止的 Worker 路径。

协议与预算定义在 `mathWorkerProtocol.ts`；调度、消费者和缓存归 `mathRendering.ts`；worker 只执行有界切片，DOM 无关的公式生成仍归 `mathEngine.ts`。

## 聚焦测量（2026-09-23）

运行 `node scripts/measure-math-worker-scheduling.mjs`。脚本从 Git 提取 `3c129ad` 作为旧实现，同时复制当前 worker 相关源码，构建独立生产配置页面。使用本机 Edge headless，3 个独立浏览器上下文，每组 5 次热态测量；不创建公式 DOM。完整输出写入 `.tmp/math-worker-scheduling/results.json`。

Atlas 的 466 处公式全部重新计算。串行组在每次调用前清空结果缓存；并发组给每处源码添加不同的 TeX 注释后同时入队，避免重复公式合并或命中缓存。直接引擎组使用相同带注释的源码。引擎和化学扩展在测量前已预热。

| 路径 | 3 个上下文中位数范围 |
| --- | ---: |
| 直接引擎，466 次 | 36.6–73.8 ms |
| 旧调度，逐式 `await` | 70.4–164.8 ms |
| 当前调度，逐式 `await` | 69.3–89.3 ms |
| 旧调度，466 个独立请求同时入队 | 96.0–115.8 ms |
| 当前调度，466 个独立请求同时入队 | 43.9–47.6 ms |

本次并发组的收益来自减少排队、定时器与串行往返，不能解释成缓存收益；当前并发组相对同一上下文旧并发组耗时降低约 54%–59%。调用方逐式等待时无法形成多式批次，不能承诺相同收益。

独立页面没有复现此前完整测量中的旧版 677–829 ms 串行成绩，不能拿该历史区间与本次结果计算加速倍数。第三上下文直接引擎结果波动明显；各路径分组测量，不据此声称 worker 计算本身比主线程引擎更快。本次只评估调度，不覆盖编辑器 DOM、滚动、字体或原生窗口。

## 合同验证

`mathRendering.test.ts` 覆盖优先级、16 条与源码预算、切片尾部重新竞逐、消费者取消隔离、原始超时、批中间超时后的已完成结果保留及尾部重试、错误不缓存、闲置释放。`mathWorker.test.ts` 以可控时钟验证 8 ms 软预算后停止继续执行尾部，并验证逐式结果和结束标记。
