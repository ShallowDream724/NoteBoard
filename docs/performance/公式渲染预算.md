# 公式渲染预算

预算定义在 `src/features/editor-md/mathLimits.ts`。它限制一次展示工作的大小，不修改、截断或回写数学源码。超限返回空 HTML、简短原因及 `MathRendering.limited`；编辑器原有点击源码入口继续可用，导出可区分预算问题和语法错误。

## 一次完整 KaTeX 渲染

| 资源 | 上限 | 检查位置 |
| --- | ---: | --- |
| 输入源码 | 16,384 个 UTF-16 单元 | `renderMath` 建立缓存键/提交 Worker 前；`mathEngine` 加载 KaTeX 前 |
| 花括号嵌套 | 64 层 | 单趟词法扫描，跳过转义字符和 TeX 注释 |
| 返回 HTML | 262,144 个 UTF-16 单元，至多约 512 KiB 字符串载荷 | 共享引擎返回/Worker 发消息前；主线程收消息后再次检查 |
| 生成 DOM | 4,096 个元素与文本节点合计 | 对 KaTeX 标记扫描计数，在任何原生 `innerHTML` 前检查 |
| 活动数学 Worker | 每次任务 2 秒 | 超时终止 Worker、返回明确原因并继续下一项 |

计数针对 KaTeX 的受控标记，不是通用 HTML 解析器。输入长度和输出长度判断为 O(1)；源码嵌套检查为 O(S)，标记计数为 O(min(H, 标记上限))，扫描附加空间 O(1)。超限时不返回任何部分公式。正常公式仍使用同一 KaTeX 配置，保留现有 `maxExpand: 1000`、MathML、矢量结构和宏的逐式作用域。

KaTeX 自身的解析成本取决于宏展开和表达式结构，不能声称为 O(S)。输出预算在 KaTeX 生成字符串后判定，因此不等于其中间树的字节级内存上限。真实桌面渲染在可终止 Worker 内进行；两秒限制控制该 Worker 的寿命，不靠延迟一次无限大的主线程插入来处理极端输入。无 Worker 的测试回退，以及直接调用共享引擎的导出转换 Worker，不具有这项单式计时中断；后者仍由导出会话整体取消。

`mathRendering` 只向共享数学 Worker 发送一个活动任务；待处理任务保留在可重排队列。订阅者共享相同表达式，最后一个订阅者取消才终止活动任务。视口队列最多保留三个已开始/已完成待提交任务，HTML 载荷最多约 1.5 MiB；LRU 缓存另有 4 MiB 总上限，包含源码键和结果。确定性的预算拒绝也缓存，避免滚动时反复计算同一个过大表达式；瞬时超时不缓存，下次可重新请求。Worker 连续空闲 30 秒后释放，已有的有界结果缓存保留。

主线程每帧最多提交两项、以 3 ms 和 32 Ki 标记单元为软调度预算。超过 32 Ki 的单式仅在滚动停下后提交，但上述输入、输出和 DOM 硬准入限制始终生效。浏览器的一次原生 DOM 插入不能中途抢占，3 ms 不是单帧耗时保证。

## 连续大矩阵

编辑器仍优先识别独立矩阵并窗口化单元格，不把整个大矩阵交给一次 KaTeX 渲染。结构读取前总源码限制为 200,000 个 UTF-16 单元，与文档可视化上限一致；超过限制直接展示可编辑源码提示。结构读取本身超过 250,000 单元格会抛出明确错误，不回落到无限制完整 KaTeX。不能安全拆分的花括号矩阵、带跨单元格状态的结构等仍按完整公式预算处理。

初始宽度使用最多 32 行、约 2,048 个源单元格的采样，不调用逐单元格 canvas 字体测量；列数本身超过 2,048 时采样至少一行，成本为 O(C)。完整结构和尺寸索引为 O(S + R + C) 时间、O(S + R + C) 空间。窗口边界查找为 O(log R + log C)，每次窗口更新为 O(V)，尺寸更新为 O(log R / log C)。

每个窗口最多挂载 4,096 个单元格。先缩小预载范围以保留真正可见单元格；连可见范围也超过上限时，在当前滚动位置明确提示，保持矩阵尺寸和完整源码。窗口内单元格的包装元素及内容总预算为 16,384 个 DOM 节点；每个位置先预留两个节点。超出的单元格显示明确提示，其他单元格仍保留；移动窗口释放空间后可重新请求这些单元格。公式前缀另外服从单式 4,096 节点上限，矩阵固定包装节点为常数。数字快捷路径也遵守单元格输入长度上限，不能用超长数字绕过检查。

每个复杂单元格与普通公式共用取消、优先级和三个准备槽位；窗口卸载会取消该单元格的订阅。总窗口 DOM 成本受上述预算约束，而非仅假定屏幕永远只能容纳少量单元格。

## 导出与验证

200,000 字符是编辑预览的矩阵入口限制，不是导出原始文档或矩阵的总源码上限。导出保留现有结构读取和矩阵续排；每个实际 KaTeX 候选段服从共享单式预算。候选被 `limited` 拒绝时应在写 DOM 前继续细分，无法安全细分的最小候选应产生明确问题；不把原式栅格化，也不把行列式拆成独立行列式。

定向检查覆盖输入拒绝、转义/注释下的嵌套计数、独立 DOM 节点上限、真实 KaTeX 输出放大、Worker 响应复核、超时后继续队列及原有取消/优先级行为。123 个学术语料均未触及新预算；普通语料中较大案例的输出约 8,124 字符、220 个元素，明显低于准入上限。该静态/单元验证不代替安装版的交互耗时测量。
