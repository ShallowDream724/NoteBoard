# 1.0.0 原生发布验收

Windows x64 Release 构建，独立 APPDATA 与 WebView2 数据目录，未使用真实用户配置或文档。基线为 rc.5（可执行文件 SHA-256 `7AE69F8E464AFBFA446C766A331A6ECD77558A8F0E323958B5CA9496D9FAB084`），新版本为 1.0.0（`B48D6C848D99825817425957A8B78C123084E13BC05400746D5AF3730F72D876`）。

## 实际桌面路径

- 四张不同 3840×2160 PNG 的宫格，1280×850 视口，每张显示约 284×161 CSS px。等待图片完成并稳定 10 秒，再对同一原生进程及其 WebView 子进程采样 5 次，间隔 0.4 秒；不强制 GC 或裁剪工作集。
- rc.5 使用原始本地图片，1.0.0 已通过实际 CSP 和 asset 协议取得图片，显示四张 512×288 Blob 预览。两次布局尺寸一致。
- 私有工作集中位数：272.12 → 273.95 MiB；Private Bytes：358.20 → 362.69 MiB。此小尺寸宫格的整应用结果没有显著改善，不能用隔离 Edge 的约 267 MiB 降幅替代它。
- 1.0.0 中 GPU 进程私有工作集约 125 MiB、renderer 约 83 MiB、browser 约 40 MiB。后续优化需继续定位合成表面、图像缓存和编辑器驻留，不能把所有占用归结为 JS heap。

较大显示尺寸的独立 Edge 实验及方法见 [显示预览测试](2026-09-27-正文大图显示预览.md)。两种运行时、显示尺寸及原图路径不同，应分别解释；显示预览确实降低了保留图像的像素量，但全应用收益取决于实际工作负载。

原生功能检查通过：宫格图片打开统一编辑器、绘制并保存到文档；示例代码未经点击即显示高亮与行号；右键复制图片并向空槽粘贴，原图和单一槽位图注均保留。没有未处理的页面异常。

## 其他验证

- 247 个前端测试文件的 1753 项断言通过。全套运行发现旧新建文档测试的异步替身被 reset 后返回 undefined；修正替身后，该入口和图片编辑共 47 项定向复查无异常。
- 94 项 Rust 库测试通过，包括原始二进制图片原子写入、错误格式不覆盖原文件及大文件确认。
- TypeScript 与图片编辑模块 ESLint 通过。ICO 的 16/24/32/48/64/128/256 七档及网页/桌面一致性验证通过。
- 真实 Edge 对比 16 组裁剪、旋转和镜像组合下的预览/Worker PNG 像素结果；另验证 JPEG/WebP 缩放输出及 EXIF=6 的手机照片方向。
- 浏览器交互覆盖 13 个绘制操作、标注移动、撤销重做、跨会话恢复、保存对话框取消、写入失败后保留草稿、760px 窗口及 WebP 导出。
