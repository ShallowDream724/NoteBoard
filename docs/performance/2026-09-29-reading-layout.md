# 阅读视图：结构、驻留内存与滚动

## 约束与实现

公式和表格各使用一个文档级阅读策略。切换不改模型、选区、序列化结果或撤销记录，也不逐块写入设置。行内公式在公式滚动模式下使用换行策略。

矩阵与表格操作共用 `core/dom/contentViewport` 的嵌套裁剪和横纵滚动宿主计算。局部矩阵滚动按自己的客户区换算可见行列；表格选择按钮使用同一边界，位于网格外侧或窄边缘，不覆盖可见文字。计算量随祖先层数增长，不遍历整张表。

编辑器与 PDF 共用 `core/math/reflow.ts` 的保守结构读取和 `core/math/layout.ts` 的候选测量。普通公式先用原有 KaTeX 运算符边界换行，只有实际超宽时才尝试两次有界结构重排。未知宏和不能安全拆分的结构保留原式；阅读视图完整适宽，PDF 继续检查字体和线条的可读下限。旧的分式专用实现已移除。

尺寸观察和模式监听共享；只为已挂载且接近视口的公式启用排版订阅。滚动不触发公式重排，旧候选在模式切换、编辑或销毁时失效。渲染继续使用原有任务队列、4MiB 结果缓存和驻留节点预算。大矩阵按可见单元格加载，长表保留稳定行壳和有限正文子树。缩放后的淘汰占位使用实际显示宽度，避免恢复成原始超宽占位。

## 浏览器验证

环境：本机 Windows，Edge 无头浏览器，1440×1000；挂载真实 TipTapEditor 和生产 Worker。执行 `scripts/check-reading-constraints.mjs`。

- 1000×4 TeX 矩阵：局部滚动至第 200、500、990 行和顶部，每次可见单元格均完整显示；驻留 140–188 个单元格。
- 千行四列表格与 30 列宽表：全文滚动策略同时生效，局部滚动后的可见正文完整，行列按钮与可见文字不相交。
- 分式、根式、成对括号、字体包装、上下叠加和大括号共 12 个独立/行内公式用例：换行后适宽，行内无滚动条，恢复自然展开后 KaTeX 标记与几何尺寸一致。
- 8 轮模式切换、跨区域滚动与强制 GC；原文完全相同，文档事务数为零，没有页面错误。

| 指标 | 测量结果 |
| --- | --- |
| JavaScript 堆，首轮 → 第八轮 | 17.70 → 17.85 MiB |
| 浏览器进程私有工作集，首轮 → 第八轮 | 429.06 → 444.98 MiB |
| 浏览器私有工作集，第三轮预热后 → 第八轮 | 445.75 → 444.98 MiB |

进程范围来自当前测试浏览器的 `SystemInfo.getProcessInfo`；私有工作集为这些进程的 psutil USS 合计，包含浏览器、渲染器与 Worker，不能与 JS 堆或 NoteBoard 原生进程内存混用。结果说明本用例在预热后保持稳定，不代表任意机器与任意文档的固定内存或帧率。

另用交付给用户的完整 `NoteBoard-export-stress.md` 复测（1500×1000）：千行表各检查点驻留 25–80 行正文，30 列表自然宽度 3840px、单列约128px；页面连续100帧滚动 p95 25.9ms，最大40.4ms，回收后 JS 堆21.57MiB、DOM50,666节点。菜单切换全文表格后仍留在当前内容处，所有阅读方式往返后原文一致、文档事务为零。

## 回归

12 个相关单元测试文件、89 项测试通过，覆盖全局策略、嵌套边界、虚拟化、拖动选取、异步取消、占位几何、资源释放及数学结构。PDF 浏览器回归覆盖 9 类内容、每类左中右三种对齐，包括嵌套长分式与根式。截图人工检查了矩阵中段、行内/独立公式以及 PDF 重排结果。

复测入口：`scripts/check-reading-constraints.mjs`、`scripts/check-long-content-viewport.mjs`、`scripts/check-export-math-overflow.mjs`。完整原始日志、JSON 和截图生成于 `.tmp`；这些测试输出不进入应用安装包。
