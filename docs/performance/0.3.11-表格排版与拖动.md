# 0.3.11：表格排版与拖动

## 行为

- PDF 完整行在页尾保留底线；同一行续页用虚线和“续”标记，重复表头。短首列标签重复，长首列和复杂内容只分段，不整段重抄。
- 网格外边线属于逻辑边缘单元格，避免表格容器的边框延伸到本页最后一行下方。跨行、跨列合并使用真实边缘，不按 DOM 第一个单元格猜测。
- 自动列宽先保留短文本/标识列的完整宽度，再为长内容分配剩余空间。自然窄表不拉满；手动列宽保留。
- 表格内公式与 PDF 共用 KaTeX 安全换行规则。列宽变化只重新排版现有 DOM，不重新渲染 LaTeX。矩阵、分式内部不会任意切断。
- 中间列边界在相邻两列间分配空间，最右边界调整表格总宽。行高是最小高度，不裁掉内容。

## 性能与归属

交互分为手势协调、临时 CSS 预览、模型属性提交三个模块。每帧只更新两条列宽规则或一条行高规则，松手后只提交一次事务。列提交采用属性批处理步骤，保持光标位置与正文子树，避免每个单元格重复扫描文档前缀。取消、销毁和其它正文变化都清理同一份预览；第二个指针不能覆盖当前手势。

大表拖动时，对无合并结构的行暂用独立 Flex 布局，屏外内容不参与逐帧排版。没有新增第二套文档或重复公式编辑器。列宽规则直接作用于列/单元格，避免祖先 CSS 变量更新导致全部后代的继承样式失效。合并表继续使用原生布局。自动列宽的普通表仍测量远处行的内在宽度，避免滚动导致列宽跳变。

应用层每帧计算和 CSS 写入为 O(1)；准备与提交包含当前表格的遍历。浏览器样式与布局仍有成本，当前完整编辑表格没有虚拟化模型，不能承诺任意规模恒定帧率。

## 定向验证

`check-table-gestures.mjs` 在真实 Edge 编辑器中检查：公式列从 650px 到 450px 时，邻列从 120px 到 320px，公式高度随换行从约 77px 到 102px。拖动中零文档事务，松手一个步骤，公式 DOM 身份保留，撤销恢复原列宽；行高从约 40px 到 80px 同样只提交一次。一万单元格、40 个指针帧的隔离检查中，拖动中仍为零事务、松手一个步骤，但最长帧约 120ms、P95 约 28ms，仍有大表布局峰值。该结果不代表完整应用或所有机器。

`check-table-export.mjs` 使用实际导出转换和排版模块生成七页 PDF：100 行数据跨页、600 段长单元格、公式与短链接。内容拼接完全一致，短链接保持一行，续行重复标签，窄表约 379px／正文约 703px。首、中间及超高行续页已渲染检查，页底线、重复表头顶线和续接标记完整，无悬空竖线。

单元合同覆盖列宽最小边界、合并结构、属性步骤的光标/DOM/撤销与序列化、布局恢复、续页内容完整性。只执行这些变动涉及的必要检查。

## 文件兼容性

Markdown 本身没有列宽、行高、三线表语法。保存时仍输出普通 GFM 表格，额外尺寸及样式写入 `noteboard-table` / `noteboard-document` HTML 注释，确实会增加源码；不是本机数据库中的隐式设置。其它 Markdown 软件通常忽略注释后显示正文，但不还原 NoteBoard 样式；删除注释会失去这些微调。跨行合并和复杂多块单元格仍属于扩展能力，不能承诺所有软件等价还原。

跨行合并或不可拆分的超高节点保留原结构并提示检查，不擅自改写其含义。PDF 仍由系统引擎完整分页；预览按页按需加载，不能与增量生成 PDF 混称。

## 打包

Tauri 入口在启动 CLI 前从 `package.json` 同步版本，再让 CLI 读取配置。前端构建钩子中的同步保留给独立 Web 构建，不能代替这一步；否则安装包可能继续标记为上一版。
