# 0.3.12：打印预览与列表裁切

## 确认的原因

1. 超宽内容列表设置了最大高度，但按钮仍采用 flex 默认收缩，项目增加时行高被压缩到文字高度以下。现在保留完整行高，列表滚动，长标签悬停可读全文。
2. 旧定位链接包住整个 KaTeX 子树。Chromium 在测试文档中产生 17,789 个 PDF 链接注释，其中一个矩阵产生 9,071 个。现在用独立定位框标记安全片段，正文不再进入链接子树；同样内容降至 1,236 个注释。
3. `@media print { * { print-color-adjust: exact } }` 在进入/离开打印模式时使约 6.8 万个元素重新计算样式。导出文档统一从根节点继承打印颜色，避免该通配规则。
4. 原生排版窗口过去先等待默认尺寸下的字体/布局，再设置最终纸张和字号，并等待固定 50ms。现在挂载正文前确定目标尺寸，资源就绪即开始。
5. 自动表格测宽原本每表交错写读。现在先跳过自然窄表，再按有界批次测量；不改变分栏和可读性决策，不建立长期测量缓存。

## 测量

输入为本机 `NoteBoard-export-stress.md`。隔离 Edge 使用实际转换和排版模块、A4、12mm 边距、10.5pt；此环境输出 78 页。它没有套用应用字体设置，也不含 WebView2 启动、主窗口快照与 PDF.js 首屏读取，不能把这里的页数或合计当作安装版完整打开结果。

| 阶段 | 修改前 | 最终两次测量 |
| --- | ---: | ---: |
| Markdown → 导出 HTML | 538ms | 513–539ms |
| DOM 挂载及字体就绪 | 1,569ms | 1,466–1,799ms |
| 内容排版 | 2,148ms | 1,800–2,020ms |
| 浏览器生成 PDF | 9,584ms | 5,484–6,549ms |
| 上述合计 | 13.84s | 9.82–10.35s |
| 单公式局部排版 | 102ms | 70–93ms |

中间仅移除打印通配样式的一次结果为 3.99s；最终重复测量高于该值，因此不使用最佳单次结果作时延承诺。系统负载和浏览器布局波动仍存在。局部排版时间不包含随后完整 PDF 重分页。

原生阶段独立运行当前 `pdf_document::prepare`，复用 release 依赖，三个独立进程取中位数：旧 PDF 的加载/注释/页码/保存合计 277.9ms，新的为 25.7ms；峰值工作集约 77.1MiB → 18.1MiB。PDF 页数和合并后的 50 个对象位置记录一致，说明原生后处理不是剩余秒级等待的来源，本轮不重写原生 PDF 管线。

浏览器原始 PDF 为 4.37MB → 0.74MB；原生清除内部定位注释后输出约 0.49MB。公式仍为字体和矢量内容，没有栅格化、减少正文或删除公式语义节点。

## 架构与验证

- 位置标记由 `itemLocations.ts` 管理，与公式渲染、排版决策、原生注释提取分离。标记幂等，清理只作用于临时标记，原公式 DOM 和真实链接保留。
- 测宽副本仅存在于当前批次，批次预算 10,000 节点；单个大表独占一批。没有全文复制或跨会话缓存。
- `scripts/measure-export-preview.mjs` 保留分阶段测量、可选 CPU/打印 trace 和真实 CSS 列表几何检查。50 项列表行高约 32px、容器 240px，末项能滚动到达。
- 15 项定向合同覆盖定位框不包裹正文、错误公式仍能定位、幂等清理、矩阵分段、外链保留、局部排版以及表格宽度/续页。前后 78 页按页面坐标排序后的非空白文本一致，并检查页面渲染；第 23 页的 PDF 绘制顺序改变，但文字位置和内容一致。

浏览器仍对全文生成 PDF。首屏可见区域按需绘制不等于按页生成；这轮没有宣称复杂长文档能瞬时完成。没有关闭可访问性节点、图片/公式或降低输出清晰度来换时间。
