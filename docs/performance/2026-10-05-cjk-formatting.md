# 中文格式边界与输入验证

范围：统一文档解析、可视输入/粘贴与源码高亮中的成对标记边界；保留现有 Markdown/NB 能力限制。架构与资源所有权见 [Markdown persistence contracts](../markdown-persistence.md)。

## 功能回归

- `markdownBoundaries.test.ts` 的 63 项检查涵盖星号/下划线的单、双、三重写法，删除线、高亮、下划线，中文及日、韩文字边界，嵌套代码/公式，英文标识符，保存往返、实际撤销状态、重做和 40000 字符单文本节点。
- 完整编辑器浏览器检查使用真实 Chromium IME composition、键盘输入、剪贴板事件、源码/可视切换及格式能力守卫。Markdown 中不能自动应用的格式保留完整输入；NB 中高亮正常转换。
- 149 个编辑/导出/画板/加载测试文件的首轮运行有 1260 项通过，2 项在并行构建期间超时。停止重负载后单工作进程重跑两项所在文件，14 项全部通过：万行表格对齐事务为 30.8 ms。未调高超时掩盖失败。新增边界检查及能力回归另行通过。

## 浏览器内存口径

`scripts/check-cjk-formatting.mjs` 从初始文件真实打开 1000 段含粗体、删除线的中文文档。每轮切换到源码再回到可视模式，末尾输入一段新的中文格式，再等待 600 ms 并通过 CDP 执行完整 GC。每轮均断言 1000 段仍完整存在。

| 轮次 | GC 后 JS 堆（MiB） | DOM 节点 | JS 事件监听 |
| --- | ---: | ---: | ---: |
| 1 | 15.33 | 8876 | 449 |
| 2 | 16.58 | 8615 | 449 |
| 3 | 17.43 | 8862 | 449 |
| 4 | 17.53 | 8841 | 449 |
| 5 | 17.62 | 8841 | 449 |
| 6 | 17.73 | 8841 | 449 |

每轮新增正文及历史，因此不要求堆大小完全不变；后续三轮 DOM 与监听器稳定，未出现整套编辑器重复残留。包含双向切换、输入、自动化往返和固定等待的整轮耗时为 1.17–2.75 秒，不能将这个数字当作单次按键延迟。该测试测的是 JS 堆，不等同于整个 Windows 应用的私有工作集，也不构成无限运行无泄漏的证明。

另一次复测通过 `PYTHON` 指定含 psutil 的解释器，统计 CDP 返回的全部测试浏览器进程的 USS（私有驻留内存）。六轮为 299.58、291.06、290.38、295.11、295.92、299.61 MiB，起末相差约 0.03 MiB；JS 堆为 16.51–17.78 MiB，监听器仍为 449，最后三轮 DOM 均为 8841。这个口径包含该独立浏览器的主进程、渲染/GPU等进程，不包含 Vite/Node 或 Tauri 原生壳；不能表述成用户当前全部 NoteBoard 窗口的内存。此次整轮操作为 2.07–4.38 秒，包含相同等待和浏览器自动化。

热路径限制：仅可能完成格式的符号触发输入词法检查，匹配最多 4096 字符；源码解析缓存仅保存格式数字范围，随对应解析上下文回收；没有文档级字符串缓存、第二份持久文档或常驻额外编辑器。

## 最终原生构建核验
