# 压力文档滚动修复（0.3.8）

## 复现与测量

实际卡顿样本是 `NoteBoard-export-stress.md`，不是 Atlas。千行矩阵原来一次创建约 29,093 个 DOM 节点；限制公式个数不能限制单个大对象的成本。表格原生布局又放大了几何变化的开销。

环境：2026-09-22，本机 Edge 153.0.4234.48，开发浏览器 1400×1000、编辑容器 900×800。样本 SHA-256：`ef15b2520e6f67f310a073de59848014eea7003076e39f9ddaed5f05397abc2f`。以下为单次诊断测量，不代表 Release 多轮统计。

| 操作 | 修复前 | 本轮结果 |
| --- | --- | --- |
| 同样的两轮快速分段往返滚动 | p95 33.4 ms，最慢帧 283.3 ms | p95 16.8 ms，最慢帧 33.4 ms；仍记录一次 77 ms 长任务 |
| 120 次真实 wheel 事件往返 | 未采集 | p95 16.8 ms，最慢帧 83.2 ms；64/87 ms 两次长任务 |
| 压力文档编辑 DOM 峰值 | 55,309 | 30,552；滚动没有文档修改事务 |
| 千行四列矩阵 | 一次挂载 4,000 单元格 | 中段约 232 个单元格，首行、中段、末行及源码入口检查通过 |
| 千行四列分式矩阵 | 未采集 | 约 152–208 个单元格；快速跳转后显示完整，源码不变 |
| 10,020 单元格表格行高拖动 | 本轮修复前 p95 50 ms，最慢 516.7 ms | p95 16.8 ms，最慢 150 ms；开始/结束仍有整表布局成本 |

滚轮检查后主动 GC 的 JS heap 约 26.7 MiB，不包括全部原生进程、布局对象、字体和显存。初次打开仍有 360–480 ms 长任务，包含 React NodeView 提交和 ProseMirror 选区读取触发的布局。不能将平均帧率解释为没有卡顿。

## 模块与成本

- `core/math/structure.ts` 为编辑器和导出共用的纯结构层，保留公式源码与显式行间距。跨单元格宏、颜色状态及规则线等交给完整 TeX 渲染路径；导出不把行列式拆成独立行列式。
- 可识别的独立矩阵超过 64 行或 512 单元格时，`matrixPreview.ts` 只挂载视口及半屏缓冲内的单元格。初始化 O(S)，结构和尺寸空间 O(单元格数＋行数＋列数)；Fenwick 尺寸索引构建 O(R＋C)，滚动边界查找 O(log R＋log C)，尺寸更新 O(log R/log C)。挂载工作按实际窗口单元格数计算。
- 数值单元格直接用 KaTeX 字体，复杂单元格由共享 Worker 分批处理。保留连续括号和完整源码编辑入口；远离视口释放 DOM，异步结果检查实例身份。源文档和导出内容不截断。普通公式沿用原队列；大型花括号 `Bmatrix`、不可独立解析的结构仍走完整 TeX 路径。结构读取上限 250,000 单元格，超限显示错误。
- `EfficientTableView` 保留原生 contentDOM、选区和列宽协议，隔离大表布局。大表仍保留完整编辑 DOM。大型无合并表的行高拖动临时使用实测列宽的独立网格行；每帧只改 CSSOM，松手一次事务，取消/销毁恢复原布局。合并表保留原生布局。
- 大纲滚动定位读取 O(log H) 个实时标题位置，不扫描全部标题，也不维护随懒加载高度反复失效的全文几何缓存。
- 暂存订阅 `editorRegistry` 的 key 版本通知，每次编辑不扫描全部文档；重复 dirty=true 不复制 document Map。800 ms 处理排队 key；5 秒/失焦兜底比较已暂存版本、正文镜像和目录，未变化内容不 flush、不重写。显式保存/关闭保留权威捕获、串行写入及内容证明。批量元数据筛选避免逐标签线性查找造成平方复杂度。
- 单实例在原生建窗前预约主窗口；第二次启动在同一锁内选择或预约，再在锁外建窗。未就绪窗口仍可接收请求，不复用隐藏 PDF WebView。32 个并发请求只创建一个预约并保留全部请求。

## 验证与剩余工作

已检查矩阵首尾内容、源码编辑、滚动零文档事务；表格行列实时拖动、样式切换不换 DOM及持久化；代码块 Ctrl+A、表内切源码、双向位置恢复。定向测试覆盖尺寸索引、对数标题查找、等长修改暂存、空闲不重复暂存、失败重试、保存期间新编辑保护；Rust 窗口/队列等 52 项通过。
