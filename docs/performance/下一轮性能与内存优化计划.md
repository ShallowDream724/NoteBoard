## 架构顺序

1. **固定可复现基线**：Release、同一字体和窗口尺寸、冷暖启动分别测；记录机器、版本、样本哈希。性能记录使用有限环形缓冲，不记录全文，也不进入正文 store。
2. **统一所有权和调度**：每个文档只有一条 revision/保存通路；可视化结果是可回收派生数据；后台任务带 generation、取消和并发上限。先覆盖关闭/撤销/崩溃恢复，再迁移调用方。
3. **先移除高频全文工作**：画板手势序列化、全标签签名、多维表格全量排序和 DOM。先在实际热路径消掉复制/重复布局，再讨论 Map、对象池等微优化。
4. **实现规模相关的展示层**：普通文档保持简单；中大型文档才启用窗口化和索引。缓存按字节与时间双约束，释放后保持位置锚点。不要通过无限增加预加载来掩盖慢帧。
5. **独立推进增量分页**：编辑模型与打印模型只共享语义，不共享页面状态。单块变化可能向后传播页数，不能保证所有修改只影响一页；重排到边界状态稳定即停止，索引及已输出页面可以复用。
6. **清理旧实现**：确认所有调用方迁移且回归通过后，删除旧 timer、旧 renderer、兼容桥和失效缓存。提交前检索入口、动态 import、IPC 注册、测试引用；“看起来没用”不足以删除。

## 负载矩阵与验收方法

| 领域 | 日常 | 较大/压力 | 关键指标 |
| --- | --- | --- | --- |
| 文档与标签 | 1/20 标签，5–100 KB | 100/500 标签，1/10 万行，5/50 MB 源码 | 冷暖启动、输入 p95、模式切换、关闭、保存队列与 retained heap |
| 公式/图表 | 20/100 式、5 图 | Atlas、连续复杂式、20/200 大图、往返滚动 | 每帧主线程工作、首屏/可见公式等待、DOM、离屏后回落内存 |
| Markdown/多维表格 | 30×5、200×20 | 1000×30、1万/10万单元格；合并、高行、长文本 | 拖动/输入/搜索 p95，布局次数、挂载单元格、事务及序列化次数 |
| 画板 | 100/1000 元素，少量图片 | 1万元素、20/200 图片，拖动及历史往返 | 每次手势物化次数、历史字节数、图片解码/URL 生命周期 |
| 资源管理器 | 100/1000 条目 | 1万/10万条目、事件风暴、快速展开收起 | metadata 次数、IPC、排序/DOM、过期请求 |
| 导出 | 10/100 页、混合图文 | 1000/1万页，宽长表，千行矩阵，局部调整 | 初次生成/局部重排、峰值进程组内存、取消释放、PDF 内容完整性 |

拟定门槛需先在固定机器标定：日常输入与滚动 p95 不超过一个 60 Hz 帧周期，典型连续操作不出现 50 ms 主线程长任务；不能只报平均值。每次内容修改的热路径与变化范围有关；所有全量 O(N) 操作标明触发边界。原生进程组、JS heap、DOM、画布、图片解码分别统计，不用单一 JS 数字代替内存。

关闭/重开 100 次后比较稳定基线、缓存上限和引用链；检查任务数、observer、listener、timer、临时文件、WebView 数量是否回落。允许有界缓存，拒绝线性累积。所有优化同时跑日常样本，禁止为了极大输入让普通文档更慢。

## 未覆盖与下一轮入口

这次是源码筛查和既有实测归档，不是完整 heap/CPU profile。Mindmap、DrawIO、PlantUML、Infographic、图片解码、撤销历史/多窗口异常路径尚需逐项 profile；不存在“已排除所有泄漏”的结论。首批执行顺序：采样基线 → 画板/表格热路径 → 保存调度 → 目录与图表生命周期 → 分页引擎。每一项独立提交，并提供前后时间、峰值/回落内存和正确性结果。
