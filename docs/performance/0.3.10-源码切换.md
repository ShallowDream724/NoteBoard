# 0.3.10：源码切换与词法分析

## 原因与职责

- TipTap 3.30.1 的 MarkdownManager 默认使用模块级 `marked`。每创建一个编辑器或纯文档解析器，都会向同一组扩展 tokenizer 数组追加回调；销毁编辑器不会撤回注册。共享文档语法现在为每个编辑器和纯解析器显式注入独立的 `Marked` 实例。直接依赖固定为已经使用的 `marked@17.0.6`，没有升级解析器版本。
- 上游有序列表、任务列表的 tokenizer 在验证首行之前拆分剩余全文。普通段落也反复触发该分配。`markdownLists.ts` 用宽松的首行候选检查拦截不可能的输入；实际列表仍由原 tokenizer 解析，保留数字、字母、罗马编号和嵌套任务列表语义。
- 公式和提示块的 `start` 只需寻找当前段落的中断点。现在遇到空行即停止前探，后续块由正常的下一轮词法分析处理，避免普通段落反复搜索整份后缀。
- `sourcePosition.ts` 按活编辑器的弱引用保留最近一次映射的不可变文档根、Markdown 及一份 token/block 索引。任一表示变化后，下次切换替换索引。已识别的顶层块按二分查找，仅对两个端点所在块进行字符匹配；不在 store/history 里追加位置副本。未知扩展仍使用语义回退。
- 源码模式复用同一不可变 CodeMirror Text 的已展开字符串。源码到可视化的长度检查先于历史物化和 `Text.toString()`：超过 200,000 个 UTF-16 单元的文件继续使用源码，不创建可视化内核，也不为拒绝切换构造 Blob 统计字节数。已知文件字节数仍可随初始判定传入。

这些操作只在打开、编辑内容物化或显式模式切换时执行。光标移动和滚动不构建索引、不进行全文序列化。已有 Ctrl+/ 的窗口捕获注册及表格中的文本位置转换保持不变。

## 测量与验证

2026-09-23，在本机 Node/Vitest/jsdom 中测量同一份文档末端的显式位置映射。通过交替增加尾部空行强制重建索引；复用阶段进行 100 次双向映射，以每个方向的平均耗时统计。Atlas 为 32,062 字符、988 个顶层块；普通段落样本为 178,888 字符、4,000 个块。修前同一进程依次创建两个编辑器，后者已具有重复注册；修前记录 3–10 轮，修后 10 轮，没有在表中的修后数据中保留逐 tokenizer 计时包装。

| 样本 | 修前索引重建中位数 | 修后索引重建中位数 | 修后复用单向中位数 / P95 |
| --- | ---: | ---: | ---: |
| Atlas | 119–177 ms | 6.06 ms | 0.0051 / 0.0166 ms |
| 4,000 段正文 | 2,699–3,100 ms | 35.27 ms | 0.0286 / 0.0473 ms |

修后上述两个样本的 lexer 中位数为 4.84 ms 与 32.93 ms。十万行、1,499,999 字符的 CodeMirror Text 可以直接按长度拒绝进入可视化；该路径不需要展开字符串。微基准不包含真实 WebView 的 React 呈现、布局、焦点和滚动恢复，不能将表中数字当成用户可见的完整切换延迟或帧率保证。

定向合同共 105 项通过：独立解析器的注册数量在反复创建/销毁编辑器及纯解析时不增长；普通正文不进入上游列表全文拆分器；列表与段落中断语义；位置索引复用与两类失效；表格、嵌套块、CRLF、空正文、图表边界的双向位置；大文件长度判断；共享文档语法、序列化和表格表示。

验证命令：`node node_modules/vitest/vitest.mjs run test/editor-md/markdownLexer.test.ts test/editor-md/sourcePosition.test.ts test/editor-md/largeDoc.test.ts test/editor-md/documentGrammar.test.ts test/editor-md/serialize.test.ts test/editor-md/tablePresentation.test.ts`。

首次解析、内容变化后的索引重建以及单个很大的块仍有随内容增长的成本；复杂或非规范扩展的语义回退也可能遍历前缀。没有把整个 Markdown 解析器描述成所有输入下都线性，也没有扩大可视化模式的文档上限。
