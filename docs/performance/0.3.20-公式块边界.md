# 0.3.20 公式块边界

## 根因与处理

方括号矩阵的行距原本应为 `\\[2pt]`。报告样本中实际为 `\\\[2pt\]`；旧边界扫描遇到内部 `\[` 时拒绝外层公式，Markdown 随后把 `2pt` 单独识别成行内公式，其余矩阵成了普通正文。未闭合 TeX 花括号也会让有效的块结束标记被忽略。这是 Markdown 块归属依赖 TeX 内容有效性的问题。

现在独立公式围栏先确立 Markdown 块边界，再让共享公式引擎处理内部源码。错误 TeX 保持一个可编辑的公式节点和完整源码，使用既有错误提示；不猜测或自动改写反斜杠。编辑器和导出使用同一套 `documentNodes` / `mathSyntax`，无需分叉实现。

只对独立开头执行围栏扫描，空间为常量（不计返回源码字符串），时间随扫描区间线性增长；不构造行数组或启动渲染。没有独立围栏对时复用紧凑语法扫描，最多多扫一次。下一独立方括号开头阻止当前未闭合块吞掉下一块。没有改变公式渲染队列或正文刷新策略。

## 验证

修复前，错误矩阵被解析成单独 `2pt`、未闭合花括号丢失公式节点、内部行尾结束标记提前截断三项检查均能复现。修复后验证错误源码完整往返、错误由公式引擎报告、相邻正文不被吞掉、CRLF/缩进/注释与紧凑写法兼容。学术公式语料、Markdown 往返和相关导出检查共 179 项通过，TypeScript 检查通过。

用户给出的输出样本已逐字备份，只纠正所报告的矩阵行距一行。该文件不在源码仓库中，缺少最初版本，无法追溯两处额外反斜杠的产生过程；不据此宣称找到了历史保存行为的根因。

## 同版侧栏显隐修正

资源管理器点击文件后，普通焦点仍留在条目上，原 `:focus-within` 规则让滑块在鼠标移出后继续显示。改为悬停或内部 `:focus-visible` 时显示，拖动保持原有 active 行为。无需计时器、全局输入监听或 React 状态；原生滚动位置和内容不变。

独立 Edge 使用真实 Explorer/ScrollArea（原生操作使用桩）：修复前确认鼠标移出、焦点不可见时 opacity 仍为 1；修复后检查点击移出隐藏、键盘导航显示、失焦隐藏、拖出侧栏保持显示及松手后隐藏均通过。
