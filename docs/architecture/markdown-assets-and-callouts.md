# 提示块与文档图片

## 提示块

提示块的持久表示是标准引用块加 `[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]` 或 `[!CAUTION]`。正文是普通块节点，支持多段文字、列表、公式和嵌套引用；未识别该扩展的 Markdown 阅读器仍能显示引用正文。

`alertExtension.tsx` 负责解析、序列化及编辑器适配，正文必须由 `NodeViewContent` 承载。`alertPresentation.ts` 只保存类型、标题、SVG 路径与颜色，不能存储文档状态。标题按钮按需显示类型选择器；不用 Emoji。

## 路径和文件目录

文件选择增加可粘贴路径的入口，`normalizeFileInput` 处理 Windows 斜杠、引号及 file URI；保留系统浏览多文件功能。仅在路径入口规范化，不改写 Markdown 正文或网络链接。

目录中的文件单击或 Enter 即打开。图片成功写入或恢复后，通过 `refreshExplorerAfterWrite` 刷新相关目录，连续写入会在在途读取后补一次刷新。根目录变更后丢弃旧请求结果；刷新失败不重复保存或插入图片。

## 删除图片

- 编辑器适配层只收集语义图片节点的增删，程序化加载及模式同步不触发清理。
- `imageAssetLifecycle.ts` 串行处理决定，支持询问、保留文件、同步删除三种偏好。界面和 NodeView 不直接操作磁盘。
- 只自动清理已保存文档的专用图片目录。用户同意清理后记为待处理，服务不能主动保存正文。由会话层在正常手动保存或已启用的自动保存成功后发布 `document-saved`，再确认当前会话、正文引用与磁盘引用后调用 Rust 文件操作。保存失败不触发回收。
- 保存前撤销会取消待处理项；关闭、放弃修改或另存为导致旧会话结束时，`document-session-ended` 取消旧路径的待处理项。监听仅在有待处理项或撤销凭据时存在。
- 同一成功保存 revision 的候选统一批处理：打开的 Markdown/HTML 文档每份最多 flush 一次，原生目录扫描与回收站前后枚举各进行一次，每张图片仍有独立恢复凭据。检查前后核对会话、revision、编辑器实例及打开文档集合；原生操作期间任一证据变化，恢复本批次已回收图片。无引用证据不跨 revision 缓存。
- 已打开文档的 `null` 正文、待物化快照、失败/null/过期 flush 都是未知证据，保留文件；不会为检查强制挂载后台编辑器。其他窗口打开的 Markdown/HTML 文档无法取得当前正文时，原生层保守阻止清理；扫描或回收期间新出现这类窗口文档时取消清理或恢复已回收图片。
- 检查打开文档及当前目录树的 Markdown/HTML 引用。百分号编码、数字/常见命名 HTML 实体及 Markdown 标点转义先规范化再匹配文件名；未知实体、无效编码或读取失败保留图片，允许多保留。目录外未打开的文档不在自动扫描范围内；目录根不可访问、范围内包含无法核对的符号链接时保留文件。
- 文件移入系统回收站；撤销恢复正文引用时，通过不透明恢复凭据恢复图片。`restoreImageAssetsForContent` 接受权威正文，独立于可视化或源码编辑器，立即取消相关待删除项并排队恢复。手动保存、自动保存及另存为在写盘前等待该屏障，恢复失败拒绝写盘且保留凭据供重试。恢复不覆盖原位置已有文件。
- Rust 将阻塞扫描及回收站操作放在线程池；操作串行。引用扫描最多 4096 份文档、64 MiB 或 32768 个目录条目，超限保留文件。
- 恢复凭据只属于本次运行，最多 1024 条，达到上限保留文件。应用重启后的恢复使用系统回收站。引用扫描与外部程序写入不是跨进程原子事务。

当前自动清理入口是可视化编辑中的图片节点变化；源码中任意文本删除不自动推断为删除磁盘图片。齿轮设置 → 文件与保存 → 图片目录设置可随时修改已记住的偏好；设置页和删除确认框都写入唯一的 `settings.file.imageDeletionPolicy`。

验证覆盖解析/保存、同步事务排除、目录刷新竞态、保存失败与会话换代、源码恢复屏障、编码共享引用、未知后台正文、过期 flush、同 revision 批处理和扫描期间版本变化。原生测试覆盖编码检查与路径范围，Windows 集成测试可独立执行临时图片回收和字节完整恢复。
