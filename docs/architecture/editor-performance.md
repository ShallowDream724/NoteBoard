# 编辑器性能边界

编辑模型维持 ProseMirror 不可变树，内容、选择和撤销共享同一套语义。交互预览不序列化全文；完整保存、导出和快照仍需线性处理文档。优化同时考虑小文档固定成本，索引与额外视图仅在超过阈值时启用。

## 定位、校验和视图更新

`pnpm-workspace.yaml` 注册三个精确版本的补丁，补丁源文件在 `patches/`，锁文件包含补丁哈希。安装必须使用仓库锁文件，不能只更新 node_modules。

- `prosemirror-model@1.25.11`：至少 128 个子节点的 Fragment 懒建立累计偏移数组，使用 WeakMap 绑定不可变 Fragment。首次 O(N)，后续 findIndex 为 O(log N)；nodesBetween 从目标子节点起遍历。小 Fragment 继续顺序查找。缓存不引用节点，随 Fragment 回收，旧树与新树的索引互不污染。源码、ESM、CJS 同步。
- `prosemirror-tables@1.8.5`：changedDescendants 的有限前瞻相对于旧节点游标，未命中后前移游标。避免整表行属性改变时旧游标停在开头导致二次扫描。只有节点身份相同才跳过校验，仍校验所有变化的子树。ESM/CJS 同步。
- `prosemirror-view@1.42.2`：更新器将已知文档位置传入内部 NodeViewDesc.update，供 updateChildren 使用，避免每个已变行再次扫描前方兄弟节点。不改变公开 NodeView.update 接口；没有已知位置的路径保留原定位。源码、ESM、CJS 同步。

升级任一依赖时必须重新核对补丁适用性；上游修复等价问题后删除对应补丁。不要跨版本盲目套用，也不要维护内部历史格式兼容分支。`largeDocumentPrimitives.test` 验证 10/128/10000 块的边界定位、不可变缓存隔离、批量行属性校验访问量和章节范围。

## 应用层

详情分别见 [内容块操作](block-interactions.md) 和 [表格呈现](table-presentation.md)。块落点和章节索引随文档身份复用；指针反馈每帧最多一次。大型矩形格选区使用一个浮层，避免逐格装饰的分组成本。明确列宽的大型无合并表按行隔离布局，保留全部内容 DOM。列宽、行高变更各提交一次可撤销事务。

普通表格的属性提交为 O(格数)，首次建立索引为 O(文档/表格大小)；范围定位包含 O(log 子节点数) 查询。这里没有把完整 CellSelection 或整表布局宣传为 O(1)。大型合并选区仍走逐格装饰，完整 DOM 的样式、内在尺寸及布局也仍有成本。

## 本机测量（2026-09-25）

Windows 本机 Edge，真实编辑扩展、菜单与 DOM，3 列纯文本表格。计时夹具替代文件服务和应用历史持久化，因此结果不能代表完整保存、所有公式或合并表格。同步时间包含事务和视图更新；可见响应计时到连续两帧回调，包含浏览器布局及调度，单次测量存在波动。

| 操作 | 10 行同步 | 1000 行同步 | 10000 行同步 | 10000 行至两帧 |
| --- | ---: | ---: | ---: | ---: |
| 整表选择 | 1.7 ms | 7.7 ms | 27.8 ms | 46.6 ms |
| 首次均分列宽 | 2.7 ms | 42.6 ms | 347.7 ms | 2104.3 ms |
| 再次均分相同列宽 | 0.1 ms | <0.1 ms | 0.1 ms | 18.3 ms |
| 首次均分行高 | 1.6 ms | 9.5 ms | 114.2 ms | 404.9 ms |
| 收起章节 | 1.4 ms | 0.7 ms | 3.5 ms | 98.3 ms |
| 展开章节 | 0.7 ms | 0.9 ms | 2.3 ms | 346.3 ms |

相同夹具的优化前万行整表选择同步 3485.9 ms、至两帧 10517.9 ms；均分列宽同步 5722.2 ms、至两帧 9404.6 ms。去掉了已定位的重复扫描，但万行表首次整体改变布局仍可达到约两秒，尚不等于完整行列虚拟化。浏览器回归另检查选区滚动裁剪、单元格 DOM 复用、尺寸撤销、五位列表序号及大字体下的把手避让。
