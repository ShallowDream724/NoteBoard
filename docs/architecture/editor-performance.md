# 编辑器性能边界

编辑模型维持 ProseMirror 不可变树，内容、选择和撤销共享同一套语义。交互预览不序列化全文；完整保存、导出和快照仍需线性处理文档。优化同时考虑小文档固定成本，索引与额外视图仅在超过阈值时启用。

## 定位、校验和视图更新

`pnpm-workspace.yaml` 注册三个精确版本的补丁，补丁源文件在 `patches/`，锁文件包含补丁哈希。安装必须使用仓库锁文件，不能只更新 node_modules。

- `prosemirror-model@1.25.11`：至少 128 个子节点的 Fragment 懒建立累计偏移数组，使用 WeakMap 绑定不可变 Fragment。首次 O(N)，后续 findIndex 为 O(log N)；nodesBetween 从目标子节点起遍历。小 Fragment 继续顺序查找。缓存不引用节点，随 Fragment 回收，旧树与新树的索引互不污染。源码、ESM、CJS 同步。
- `prosemirror-tables@1.8.5`：changedDescendants 的有限前瞻相对于旧节点游标，未命中后前移游标。避免整表行属性改变时旧游标停在开头导致二次扫描。只有节点身份相同才跳过校验，仍校验所有变化的子树。ESM/CJS 同步。
- `prosemirror-view@1.42.2`：更新器将已知文档位置传入内部 NodeViewDesc.update，供 updateChildren 使用，避免每个已变行再次扫描前方兄弟节点。不改变公开 NodeView.update 接口；没有已知位置的路径保留原定位。源码、ESM、CJS 同步。

升级任一依赖时必须重新核对补丁适用性；上游修复等价问题后删除对应补丁。不要跨版本盲目套用，也不要维护内部历史格式兼容分支。`largeDocumentPrimitives.test` 验证 10/128/10000 块的边界定位、不可变缓存隔离、批量行属性校验访问量和章节范围。

## 应用层

工具栏实现随 Markdown/原生编辑器按需加载；文件打开预取同时启动编辑器与工具栏，二者不互相等待。已加载组件跨标签复用，外壳始终保留工具栏高度，避免完成加载时正文跳动。工具栏加载失败只显示本地重试入口，不卸载正文。构建分包仅将明确指定的模块放进重库 chunk，React 规则匹配真实包目录，避免公共弹层依赖被画板吸入、或把 @tiptap/react 误当作 React 运行时。首屏预算仍由生产产物的传递依赖闭包检查，不靠 chunk 改名绕过。

保存、身份迁移与外部重载通过 `core/editor/pendingSnapshots` 的同步屏障访问未物化输入。富文本内核加载时注册处理器，之后才可能产生待提交快照；没有加载过内核时没有这类快照。屏障保留原同步事务次序及卸载后数据归属，不为调用保存屏障而在首屏加载整套 Markdown parser、schema 和源码样式映射器。

详情分别见 [内容块操作](block-interactions.md) 和 [表格呈现](table-presentation.md)。块落点和章节索引随文档身份复用；指针反馈每帧最多一次。大型矩形格选区使用一个浮层，避免逐格装饰的分组成本。大型无合并表保留全部模型与行占位，仅挂载可见缓冲区及选区端点的单元格；装饰也只覆盖这些行。列宽、行高变更各提交一次可撤销事务。

普通表格的属性提交为 O(格数)，首次建立索引为 O(文档/表格大小)；范围定位包含 O(log 子节点数) 查询。这里没有把完整 CellSelection 或整表布局宣传为 O(1)。大型合并选区仍走逐格装饰，完整 DOM 的样式、内在尺寸及布局也仍有成本。

## 内容导入与视图验收（2026-09-25）

Edge 153，真实生产扩展和剪贴板 Worker。最终共享适配器上普通段落、Word 样式段落及 20×4 表格各运行五次：处理事件/完成导入中位数分别为 4.8/4.8、6.6/6.6、9.5/9.5 ms；冷启动最大事件耗时分别为 28、39.2、17.7 ms。十五次均未启动 Worker，无 LongTask；最长帧间隔最大分别为 63.6、42.2、24.1 ms。该轮同时有构建任务，数值高于早先空闲测量；小输入始终保留直接路径，不为异步架构承担固定 Worker 往返成本。

最终共享管线复测 10,000×4、726,685 字符 HTML 表格：事件响应 5.6 ms，Worker 规范化 352.9 ms，分片构造 117.1 ms，最终事务 106 ms，导入合计 580.8 ms，最大帧间隔 150 ms。记录到 92/148/80 ms 三个长任务；该案例没有一秒以上冻结，不代表所有体量恒定耗时。DOM 元素由完整渲染的 90,010 降至 10,306，模型仍包含 10,000 行。这里区分事件响应、完成时间和最长帧间隔，不把异步任务说成已经瞬间完成。

同规模原生表初次创建 261.2 ms；定位第 7,000 行同步挂载 4.5 ms，编辑、撤销、重做正确；整表选择 46.7 ms，可复制全部 10,000 行。显式列宽提交 234 ms，完整导出含最后一行。滚动中约挂载 160–252 个单元格，浏览器无异常。

同规模新页面滚到第 5,005 行，未强制 GC 的 CDP 基线：JS 已用堆 26.8 MiB、已分配堆 60.7 MiB，正文包含 10,498 个活跃元素、244 个已挂载单元格。CDP 原始节点计数 21,261 包含未回收对象，不能与活跃 DOM 元素数混用。这是该夹具当前进程的观测值，不等于应用总内存，也不能从 DOM 降幅推算同等内存降幅。

首行已卸载时的真实鼠标操作：行/列排序最大帧间隔分别 537/506 ms，列/行缩放 282/45 ms；均分列宽同步 343 ms、帧间隔 363 ms，均分行高 103/118 ms。手势预览不产生内容事务，松手提交一次，撤销恢复原内容和尺寸；列手势中表高与屏外行占位高度保持不变。行替换/撤销后复用最近的 IntersectionObserver 结果同步已挂载窗口，不用全文几何重测。

原生模型/历史仍为 O(完整内容)，视图为 O(行占位 + 可见单元格)；复制、存盘和导出仍读取完整内容。含合并格的大表暂保留原生完整布局。夹具覆盖真实编辑插件与浏览器，但未包含文件服务和应用历史持久化，也不代表任意硬件、任意嵌套内容的性能上限。

Windows 本机 Edge，真实编辑扩展、菜单与 DOM，3 列纯文本表格。计时夹具替代文件服务和应用历史持久化，因此结果不能代表完整保存、所有公式或合并表格。同步时间包含事务和视图更新；可见响应计时到连续两帧回调，包含浏览器布局及调度，单次测量存在波动。
