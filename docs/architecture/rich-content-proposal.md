# 图片组合、折叠内容、补充说明与富文本交换

状态：方案草案，供讨论；本文所列新功能尚未实现。已有拖拽与性能修复独立交付。

## 产品与存储原则

`.nb` / `.nbdoc` 使用同一个原生结构化文档。当前文件是 UTF-8 JSON envelope，正文是 ProseMirror JSON 树，不是 HTML 文件。保留这一方向：功能由明确的节点、标记和受约束属性描述，HTML 只用于导入、呈现和导出。内部预发布格式可以直接调整，不建立旧测试版本迁移层。

文档内容与阅读状态分开。图片顺序、空槽、标题、说明正文、模糊标记属于文档；当前轮播页、临时揭示、浮窗固定位置和尺寸属于本机阅读状态，不进入内容撤销。修改说明正文、删除图片或移动内容必须进入统一文档事务与历史。剪切粘贴引用实体时重映射 ID，不能让两个副本意外共享可编辑说明。

不把图片 Base64 复制进每次正文历史。已保存文档继续使用受管理的相对图片引用；未保存时先暂存资产。图片组合内仍使用统一图片节点，让引用扫描、复制、另存为和清理遍历子内容即可覆盖。独立的便携打包不是此次必需范围。

## 内容语义

### 图片组合

一个 `imageCollection` 容器，两个展示模式：拼图和轮播。四宫格为 2×2，六宫格为 3×2，九宫格为 3×3；模板只设置布局和槽数量，不生成多套编辑器。每个 `imageSlot` 是独立子节点，可包含一张图及图注，也允许为空。布局切换保留原有图片顺序，不因模板槽位减少删除图片；不足容纳时增加行或先拒绝缩小。

轮播名称使用“图片轮播”：左右翻页按钮、当前位置圆点，不自动播放。空槽编辑时可见；阅读时跳过空槽；打印拼图仍保留用户指定的空槽位置。当前图及相邻图按需解码，远处图片使用缩略图/占位，不将所有原图同时挂载。打印使用单独的完整内容投影，绝不从当前屏幕上可见的一张图截图。

从外部拖图片到正文时显示块插入线；进入已有图片槽时显示槽高亮，避免同时显示两个竞争目标。粘贴到空槽就填槽，多个图片按顺序填充后续空槽，容量不足时追加槽；粘贴到正文则插入图片块。异步读取保存期间目标随文档事务映射，取消或切换文件不写到新位置。一次批量插图作为一个文档操作撤销。

### 折叠块

`disclosure` 有可编辑标题和 `block+` 正文，与标题章节折叠区分。它可以放在普通正文中，整个块拖动、复制、删除；内部编辑保持标准块语义。建议允许结构性嵌套，但导入深度遵守统一解析限制。默认展开/折叠可作为文档属性；临时阅读切换只保存本机状态。

### 模糊内容

“模糊”作为可揭示的显示样式，作用于文字/行内节点，也可作用于选中的内容块；原文始终保留。悬停或键盘聚焦揭示，移开恢复。它不承担保密或脱敏语义。打印、Word 和 Markdown 默认完整揭示，导出摘要明确标记“模糊效果已移除，内容完整保留”。如以后增加真正脱敏导出，必须成为单独的显式操作。

### 补充说明

菜单名称“添加说明”，阅读时叫“补充说明”。锚点有细虚线下划线与小问号，悬停文字或标识均可打开。说明正文独立保存一次，锚点引用 ID，避免长说明在每个文本片段的 mark 属性中重复存储。行内与块级锚点共用说明实体。

正文树与说明实体属于同一个文档状态和事务边界，删除最后一个锚点、恢复、剪贴板导入均可原子撤销。具体实体位置需要与现有 ProseMirror/文档历史接口一同落定；不要先引入一套独立且不可撤销的 React 状态来存内容。

浮窗采用按需加载的富文本内容，默认随内容增长且有最大视口尺寸。鼠标从锚点移向浮窗时有离开缓冲；离开二者后关闭。固定后可在编辑面板内拖动、调整尺寸，视口变小后约束回可达位置。只挂载当前打开或固定的说明，固定窗内容编辑也提交到文档事务；拖窗只改阅读状态。首版说明不再嵌套说明或可固定浮窗，防止交互递归。长正文与图片可以放入说明。

## 菜单组织

- 顶部现有图片入口改为“图片”悬停菜单：插入图片；分隔；四宫格、六宫格、九宫格、图片轮播。保留图片图标，不用含义模糊的手形图标。无需再嵌套一层“模板”。
- 插入更多：折叠块归入内容结构组；与代码块、引用/提示块靠近。已有图片入口与命令目录使用相同 action 定义，不复制命令实现。
- 选区工具栏：常用文字样式直接显示；“添加说明”“模糊”归入更多操作。未选择合适内容时不显示。已有说明则显示编辑/移除，不同时堆放创建按钮。
- 图片/组合的块菜单只显示相关布局、替换、图注、复制、删除；表格与普通文本菜单继续按能力筛选。
- 所有菜单由共享 capability、分组和排序定义产生；一级和二级菜单共用悬停开启、跨区域延迟关闭、箭头动画、键盘焦点规则。悬停已开启后点击不得反向关掉；颜色主按钮保留重用配色的动作。

## 剪贴板边界

统一 `clipboardImport` 接收本次剪贴板快照，经过分类、解析、规范化和 schema 校验，产生一个 `DocumentSlice + assets + diagnostics`。表格插件、图片插入和普通 HTML 不再各自抢占 paste 事件。优先级：可信且通过校验的本应用结构化片段 → 可解析 HTML → 纯图片文件 → 明确的 TSV 表格/纯文本。HTML 已包含图片时，剪贴板附带的 PNG 不能让文字被吞掉或让同一图片重复插入。

Ctrl+V 默认保留可表达格式，Ctrl+Shift+V 及菜单“仅粘贴文本”明确绕过富文本。网页/Word 的加粗、斜体、列表、链接、文字色、高亮、对齐和可读图片映射到已有语义；Excel HTML 表格映射为原生表格，保留可表达的合并、对齐和底色。只有文本时，表格上下文或明确多行 TSV 才推断格子，不能把任意代码里的制表符变成表格。

Office 特有标签、列表标记和样式通过有边界的导入适配器处理，不把 mso-*、脚本、事件属性或未知 HTML 带入原生格式。表格单元格导入显示值；不承诺 Excel 公式引擎。仅剪贴板暴露出的数据可转换，不能凭空恢复 Word 中未提供的公式、浮动对象或图片。不可读取图片保留替代文字/来源和可见占位，并给出具体结果说明。

解析器单次遍历与输出量成正比；不挂载完整外来页面测 computed style，不执行外来脚本。大 HTML/Office 片段可在 Worker 中规范化，资源异步解码/落盘有界并发；最终一次事务插入。验收覆盖中英文 Office、样式表 class、mso-list、Excel 合并/空格/换行、HTML 与 PNG 同时存在，以及撤销重做。

## 导出契约

每种节点/mark 注册明确投影和能力诊断。导出返回内容与降级摘要；对未知内容节点失败或指出具体位置，不再通过默认递归悄悄丢掉节点自身语义。布局丢失可接受，文字、图片引用、图注、隐藏正文和说明正文不可静默丢失。

| 内容 | 干净 Markdown | HTML | PDF / 打印 | Word / LaTeX |
| --- | --- | --- | --- | --- |
| 图片拼图 | 按行优先顺序导出全部图片和图注；空槽不输出伪造文字 | 保留网格与空槽 | 保留网格与空槽 | 映射为含图片的原生表格，必要时顺序展开 |
| 图片轮播 | 全部图片依序导出 | 保留轻量翻页交互；打印样式展开 | 自动排成完整网格，跨页继续 | 静态网格或顺序图片 |
| 折叠块 | 标题加完整正文 | details/summary | 全部展开 | 标题加完整正文 |
| 模糊 | 输出完整清晰内容 | 保留揭示交互 | 完整揭示 | 完整揭示 |
| 补充说明 | 编号引用 + 文末说明；可选支持脚注的 Markdown 方言 | 锚点与静态可访问的说明，增强悬停 | 文末说明并保留编号 | Note/脚注，复杂说明用文末章节 |

普通 Markdown 路径不额外引入私有注释或 HTML 组件。复杂原有表格目前仍可能用标准 HTML 导出完整内容，这一边界应明确；新增图片组合不应迫使普通图片导出 HTML。支持脚注是目标方言能力，不把所有 Markdown 阅读器都假定为支持脚注。

HTML 导出需独立 renderer，避免当前仅走 Pandoc 的通用 HTML writer 丢掉交互；采用小型静态增强脚本，移除脚本时所有图片和说明仍在内容流中可读。PDF 继续使用现有浏览器打印链路；Pandoc 为 Word/LaTeX 接收目标化 AST，不接收整段 RawBlock HTML。导出提示只列出本次实际存在的降级，如“1 组轮播已展开；2 处说明移至文末”，不做每次阻塞确认。

## 调研证据

本机 Pandoc 3.2 的一次性样本：同一段 details/summary、blur span、2×2 图片表格（两张图、一个空格、图注），分别作为 RawBlock HTML 和经过 HTML reader 的结构化 AST 导出。原始 HTML 路径生成的 DOCX 丢掉该块全部正文和图片，且无警告；结构化路径在 DOCX 保留所有四个正文标记和两张图，原生 Note 正文也保留。LaTeX 结构化结果包含展开正文、两次 includegraphics 与 footnote；这里没有声称已编译验证 PDF 外观。该实验验证边界，不代表新组件已经实现。

- [Pandoc 架构与格式限制](https://pandoc.org/MANUAL.html#description)：reader/AST/writer，转换不能保留任意排版。
- [Pandoc Raw HTML](https://pandoc.org/MANUAL.html#extension-raw_html)：原始 HTML 仅在部分输出格式透传，在其他格式中被抑制。
- [Pandoc Table Cell](https://pandoc.org/lua-filters.html#cell)：结构化格子支持块内容及行列跨度，可承载静态图片网格。
- [Clipboard API mandatory types](https://www.w3.org/TR/clipboard-apis/#mandatory-data-types-x)：对应原生类型存在时，paste 事件暴露 text/plain、text/html、image/png；这不等于任意 Office 私有格式都可读。
- [Microsoft HTML Clipboard Format](https://learn.microsoft.com/en-us/windows/win32/dataxchg/html-clipboard-format)：HTML fragment 与其上下文有明确交换格式，原生适配仅在 WebView 数据不足且有真实样本时补充。

## 实施顺序与验收

1. 定义节点/说明实体与统一导入输出接口，先写内容守恒、撤销、资产引用的行为样本。
2. 图片组合与轮播、插图/拖放落点、完整打印投影。
3. 折叠块与模糊，随后补充说明及浮窗层。
4. Word/Excel/网页实样本规范化，菜单统一检查和所有导出格式验收。

按小文档与大文档分别测量，不能以异步隐藏算法问题。遍历成本至少与输入/输出量成正比；轮播切页和浮窗移动不能扫描全文，粘贴和导出不能逐节点重算文档前缀。图片二进制解码、缩略图内存、活动浮窗数量和一次导出峰值分别测量。
