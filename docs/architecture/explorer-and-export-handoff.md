# 目录更新与导出交接

## 目录状态

`explorerStore` 始终只持有一份目录树。`workspaceRoot` 是用户通过打开文件夹或打开目录建立的工作区；`root` 是当前显示的导航目录，显式定位外部文件时可以暂时不同。标签只携带可选的 `explorerContext: { root, source }`，记录 `workspace`、`tree`、`parent` 或 `locate` 来源，不保存展开集合、目录节点或缓存。手动打开工作区不批量改写标签的来源。

`setRoot` 在实际换根时清空旧目录缓存、展开状态与定位，并递增 `rootRevision`；同根调用只更新条目。刷新统一使用 `refreshExplorerDirectory`，不能借换根重建树。手动刷新只访问根目录和已展开目录，最多四个并发请求，不递归发现闭合目录，不读取文件正文。体积为 1GB 的附件和 1KB 的附件都只是一个目录条目。

同一根目录版本与隐藏文件设置下，同目录读取共享在途请求。读取期间发生的新刷新会标记 dirty，在当前读取完成后再读一次，避免吞掉连续写入。完成或失败后删除在途记录，不形成第二套永久目录缓存。根目录切换后放弃旧结果，即使迅速切回原根也不会复用旧版本读取；节点展开同样校验版本。缓存只接收当前根范围内的目录；已有缓存分支被删除时，移除对应展开状态和后代缓存。切换许多标签不会积累许多目录树，内存仍与当前根下已浏览条目的数量相关。

`followExplorerFile` 是被动标签跟随：工作区包含目标文件时始终使用工作区最高根目录，保留其他展开分支，只展开并滚动到目标的祖先链。工作区外的普通打开不会自动离开工作区，也不读取外部父目录。`revealExplorerFile` 是显式定位：允许进入外部目录，仅为活动标签保存该导航；切回其他标签会恢复其根目录。外部标签已有包含目标的树来源时，定位沿用该来源，不能退化为最深的直接父目录。面包屑导航也只改变当前标签的显式导航。

文件树的点击、Enter、菜单打开与树内新建都在异步准备之前捕获显示根目录。没有手动工作区时，系统直接打开文件可使用直接父目录；从该树继续打开深层文件则继承树根。工作区 A 已存在、用户定位到外部 B 后，从 B 树打开的深层文件也继承 B，并在以后切换与定位时沿用 B。已有标签被重新打开或被所有者激活时保留其来源。递增的导航代次、根目录版本及调用者有效性检查共同阻止旧异步结果抢回后来的手动导航。

文件关联的冷启动与单实例转交由打开队列统一传入 `explorer: 'parent'`：正文建好标签后立即返回，目录跟随与缓存结果应用在 `requestAnimationFrame` 后的下一任务执行，先给正文绘制机会，保持侧栏原有显隐，并遵守工作区与标签来源策略。若文件属于其他窗口，当前窗口将规范路径及原始 `cli` / `second-instance` 来源放入所有者的既有打开队列，再用 `nb://open-requests-available` 唤醒并聚焦所有者；所有者从 `already-open/self` 分支激活与跟随，不重新读正文，也不继续转交。当前窗口不读该文件的目录。导航在正文准备前预留代次；准备期间出现更新的手动导航时，本次激活保留当前树，来源仍可在以后用户切回时使用。自动标签跟随不抢占显式打开的准备及跟随阶段。

会话以兼容的可选字段保存 `explorerWorkspaceRoot` 与每个标签的 `explorerContext`，恢复仍只创建懒标签并保持 Home。工作区与显示目录独立校验；显示目录已不存在或读取失败时回退到仍存在的工作区，同根只检查和读取一次。工作区也不存在时解除固定，不丢弃可恢复的标签。旧快照没有来源字段时，将包含文件的旧 `explorerRoot` 作为树来源，否则使用直接父目录；不推断旧根曾是手动工作区。恢复期间用户开始的新导航优先。目录重命名同步更新工作区、标签来源根与当前缓存路径，换根丢弃旧缓存；另存为或跨根路径更新会解除已不再包含目标的树来源。关闭标签后来源随标签释放。

新文件打开失败或大文件确认取消后，仅当该请求仍拥有当前导航时，恢复活动标签被打断的被动跟随，继续遵守工作区、显式来源与导出保留策略。后来的打开请求或手动目录导航优先，失败请求不能抢回资源管理器。

`explorer: 'preserve'` 用于导出结果的标签激活：不切换根目录、展开目录、改变定位或侧栏显隐。`activateWithExplorerPolicy` 在激活前作废旧定位结果，将保留策略限定为当前一次激活；`followExplorerFile` 因而也会跳过稍后触发的 React 跟随效果。用户离开该标签时通过窗口状态订阅释放策略，之后切回继续普通跟随；显式定位按钮始终可用。新文档、已打开文档和注册竞争均走同一激活入口。目录没有文档标签，`preserve` 的目录请求返回失败且保持 Explorer。

`refreshExplorerAfterWrite` 仍作为已确认文件写入的入口，按祖先链刷新，从而发现新建的资源目录。刷新错误不会将已经完成的写入重新执行。系统目录监听和手动刷新共用相同的隐藏文件设置。

## 导出成功

导出引擎只负责生成与保存。`ExportModal` 在保存确认后关闭，并交给 `presentExportedFile`：用 `probeDocument` 读取实际文件大小，在成功 toast 中显示字节数。所有格式均以 `explorer: 'preserve'` 打开文档；HTML 标签默认进入隔离的阅读预览，保留源码、浏览器打开与资源管理器定位入口。当前根包含导出目标时独立刷新祖先目录条目，刷新不阻塞打开，也不定位文件。大小读取失败时仍显示成功并继续打开；转换警告独立显示。读取大小、刷新和文件展示失败均不能变成“导出失败”。HTML 标签细节见 [HTML 文件与源码编辑](html-source.md)。

导出附件的 `exportNotice` 只属于当前标签生命周期。`UnsupportedView` 复用文件名、大小和默认程序/系统管理器/复制路径动作，带 receipt 时显示“导出成功”，不再发格式不支持的 toast。关闭标签即释放，不写入 Markdown、历史或设置。

## 路径与示例

Ctrl+O 的路径输入接受文件和目录，校验只判断存在性，随后统一交给 `prepare_document` 分派。Windows 原生文件和目录浏览保留各自选择器，放在同一个入口中。

功能示例为随包 Markdown，按需加载成未保存副本，主页可随时重新打开。首次空配置、空启动且没有恢复标签时显示一次；既有配置、显式打开和会话恢复不被示例替换。打开前再次检查空标签条件，避免异步模块加载覆盖用户操作。
