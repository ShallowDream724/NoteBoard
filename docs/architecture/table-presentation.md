# 表格尺寸与文档样式

## 数据归属

- 列宽存于 Tiptap 表格单元格的 `colwidth`，行高存于 `tableRow.height`，单位为 CSS px。行高是最小高度，内容较多时继续撑开，不裁切文字。
- 标准表 / 三线表属于当前文档，使用一个位于文档开头的 `documentPresentation` 元数据节点。编辑器容器通过 `data-table-style` 继承样式，新增表格和重新进入视口的内容自动使用当前样式。
- 不修改根 `doc` 的属性：实测该操作会使 ProseMirror 重建全部 NodeView。元数据节点使用普通事务及撤销历史，保留正文子树和现有 DOM。它不可选、不可拖动，也不参与可见正文的位置映射；正文开头退格不会删掉它。
- `tablePresentation.css` 是编辑与 PDF 共用的外观规则；菜单和拖动光标独立放在 `tableControls.css`，不进入导出页面。

## Markdown 保存约定

Markdown 原生不表示列宽、行高和文档表格样式。因此仍保存紧凑 GFM 表格，额外数据放在 HTML 注释中，普通预览器忽略注释后仍能显示表格内容。

```md
<!-- noteboard-document {"version":1,"tableStyle":"three-line"} -->

<!-- noteboard-table {"widths":[80,240],"heights":{"1":64}} -->
| 编号 | 说明 |
| --- | --- |
| 1 | 内容 |
```

文档注释放在开头；尺寸注释紧邻所属表格。`widths` 中 0 表示自动列宽，`heights` 只保存人工调整过的行。恢复标准样式及重置尺寸后移除不再需要的元数据。合并单元格、混合表头和无表头结构另外使用稀疏 `rows` / `noHeader` 字段，避免调整样式后保存时丢失这些结构；其他 Markdown 软件不保证还原这些扩展结构。

`markdownTable.ts` 负责唯一的读写实现，编辑器、Worker、PDF、Pandoc 的输入共用它。注释长度和字段形状有边界检查；无效扩展按普通 Markdown 输入处理。序列化不按最长单元格补空格或分隔线，长内容不会再使每一行膨胀。源码大小为 O(正文及结构元数据大小)。

## 交互与性能

`tableSizing.ts` 统一拥有行、列手势，列边界命中优先；停用上游独立的列缩放插件，避免两套监听和装饰竞争。中间列边界在相邻两列之间分配空间，表格总宽不变；最右边界调整总宽。窄于默认下限的已存尺寸仍按实际可用空间约束，不产生负宽。行高仍是最小高度，内容不能被裁切。

`tableGesturePreview.ts` 在开始时读取并固定列宽，每个动画帧最多更新两条列宽 CSS 规则或当前行的高度规则，不修改内容 DOM 属性，不发送文档事务。大且无合并结构的表格在手势期间使用独立 Flex 行并跳过远处内容排版；合并表保留原生结构。列宽不通过祖先 CSS 变量向所有单元格继承，避免每次拖动使整个后代树重新计算样式。普通自动列宽表不跳过远处行的内在尺寸，防止初次测量或滚动改变表格自然宽度。

松手撤掉临时样式并提交一次事务；取消、Escape、其它正文事务和销毁都清理同一个手势，第二个指针不会接管或结束它。块拖拽把手暂停命中与定位。`TableColumnWidthsStep` 只批量修改当前表格的单元格属性，保留子内容和文档位置；反向步骤恢复原来的自动/显式宽度，支持标准撤销和序列化。没有逐单元格重复定位文档或整篇替换。尺寸重置仍只遍历当前表格。

全文样式切换只修改一个元数据节点及容器属性，不逐表调用命令、不重新解析 Markdown、不重建公式或表格视图。浏览器仍需为已挂载表格计算样式和必要布局；这部分成本不是 O(1)。三线表边框略厚，切换可能产生少量高度变化。正常的延后保存仍需线性序列化文档。

手势准备读取 O(列数) 几何，并检查当前表格的合并结构；每帧应用层指针计算和 CSS 写入为 O(1)。列提交和逆向快照遍历当前表格，普通表为 O(单元格数)，合并表另含稀疏跨行占用区间的维护成本；不按每个单元格重新扫描文档前缀。浏览器仍有布局和样式计算，完整可编辑表格没有行列模型虚拟化，不能把应用层常数次写入描述成任意表格恒定帧率。

单元格内的公式通过 `core/math/wrapping.css` 与 PDF 共用 KaTeX 安全换行边界。列宽改变时由 CSS 重新排版已存在的公式 DOM，不重新解析 LaTeX、不再请求 Worker、不新增嵌套公式滚动容器；不可分割的矩阵/分式内部仍不被任意拆开。

## 与 PDF 的配合

PDF 读取同一份行高、列宽和文档样式。普通表格按自然宽度显示；自动宽表先测量自然宽度与最小内容宽度，优先保留短文本列的完整宽度，再把剩余空间分给长内容。公式在 KaTeX 原生 `base` 安全边界换行。无法合理容纳的多列表格再按列分组，并重复首列。各组保留列宽，最后一组不会为填满正文区域而拉宽。

纵向分页重复表头，不按表格总高度缩小。标准表使用分离边框与单边网格，使完整行在页底保留底线。外边线归属逻辑边缘的单元格，表格容器不绘制边框，因此页底不留下悬空竖线，表头顶线随重复表头出现。边缘标记识别跨行及跨列合并，三线表的上下粗线也归属相应单元格。高于一页正文区域的行按测得的文本字符位置及完整公式节点拆成有界续行；包装标签和链接随片段保留，KaTeX `base` 不拆开。续行以虚线和“续”标记连接，首列只有在不超过 80 个 UTF-16 单位、约 2.5 行且不含公式/图像等复杂内容时才重复；长首列只分段，不整列重复。具有跨行合并的表格或仍不可拆分的超高节点保留原结构并给出检查提示，交由浏览器原生分页。

显式列宽超出页面且无法分组时，保留尺寸并指出问题，允许用户调整列宽或选择适宽缩放；不在导出时悄悄覆盖手动数据。合并单元格的按列续表尚未实现。Pandoc 仍负责其他格式的布局，本轮没有把 PDF 的 CSS 尺寸和三线表外观强行转换成 Word/LaTeX 样式。

`tableLayout.ts` 只测量本次变化且受到宽度约束的自动表格；自然窄表直接保留现有宽度。临时副本以 10,000 个 DOM 节点为批次预算，单个更大的表格独占一批，工作空间为 O(max(单表节点数, 批次预算))。同批集中写入、读取自然宽度，需要分配长内容列时才继续测最小宽度，避免逐表交错写读。正常或异常退出均清除副本。`layoutPolicy.ts` 在不低于可读下限的最多四档缩放中搜索连续列组：优先减少分段，同时惩罚过度缩小与末组空白。动态规划向前最多查看 128 列，时间 O(4×128×列数)、工作空间 O(列数)；实际达到可用宽度即停止扫描。复制 O(输出单元格数)，重复首列计入输出成本。

`tableContinuation.ts` 只检查变化的表格，对跨页文本采用单字符范围测量与二分边界搜索，不在每一步测量全文或克隆剩余长尾。每个原始叶节点只复制到其输出片段，包装节点的复制量与输出结构成正比。仅实际拆分的表格保留恢复快照，局部选项变化先恢复该表格再重新排版。这些策略是有明确候选集和安全边界的近似视觉优化，不宣称任何内容下的审美全局最优。PDF 原生分页仍按全文生成，预览画布按页按需挂载，两者不能混称为增量分页。

## 验证

定向回归覆盖尺寸/样式保存往返、源模式双向光标映射、合并结构、无效元数据和撤销；浏览器覆盖真实行列拖动（拖动中零文档事务，松手一次）、样式切换保留所有表格/公式 DOM，以及恢复源码后的尺寸。宽表导出核对全部单元格、重复表头与手动行高。
