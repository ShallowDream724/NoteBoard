# Code visibility and rendering

## Standalone source files

When a CodeMirror source file contains a logical line of at least 400 characters, its status bar offers 长行阅读. JavaScript and TypeScript use the current syntax tree to add visual breaks and indentation at statement and container boundaries. Strings, templates, regular expressions and JSX text stay intact. Other languages and inputs that exceed the parse or decoration budget use a 100-character reading measure with hanging indentation and soft wrapping.

The layout belongs to the mounted file and clears on the next source edit or when the reader exits it. Source offsets, selections, copied text and persisted content remain authoritative. Long-line detection uses CodeMirror's immutable text cursor in deferred batches, checks changed lines when possible, and cancels when the editor is released. Structured reading uses at most 192 Ki UTF-16 code units of input and fewer than 2,500 display breaks, with no startup parser dependency.

## Rich-document code blocks

Code blocks activate from their actual intersection with the editor scroll area and the browser viewport. Editor focus and selection are not activation signals. `codeVisibility.ts` owns one geometry service per mounted editor. Mount, scroll, editor/block resize, and ancestor visibility changes request a single animation-frame measurement. The service reads geometry before consumers write decorations. Hidden parked tabs deactivate even when their code descendants explicitly set `visibility: visible`; restoring an unchanged-size tab requests a fresh measurement through its ancestor attribute observer.

This deliberately does not use the shared rich-content `nearViewport` intersection-observer history. An initial zero-height observation may be discarded there, and a tab moving back at the same dimensions does not provide a reliable independent recovery event. Code measures the current layout on its own scroll events even when IntersectionObserver emits nothing.

Line-number/fold controls and syntax colors subscribe independently to the same service. Controls batch one transaction per editor measurement and never wait for the syntax worker. Code structure accepts 10,000 logical lines and 512,000 characters; folding retains its smaller 2,000-line/128,000-character parsing budget. Gutters reserve up to five digits. Blocks longer than 400 lines render a window of up to 400 gutter widgets, with 24 lines of overscan around the actual viewport.

Syntax parsing stays in the shared cancellable worker. Its source budget is 512,000 characters and its token budget is 131,072 tokens / 12 MiB. The main thread binary-searches the returned tokens and installs only the current line window for long blocks, preserving whole-source grammar context without thousands of offscreen spans. A visible block retries transient worker failures; scrolling it out cancels work and removes colors. Unsupported languages and source/token budget overflow retain readable plain code.

While a code block is under IME composition, syntax and line-control presentation transactions wait for composition completion and ProseMirror's final DOM read. The controls plugin maps existing decorations through interim document changes instead of tearing down and recreating widgets or chunk spans around the preedit text. Pending work is coalesced, then checked against the current node before publication. This keeps the editable code DOM owned by ProseMirror throughout preedit while restoring colors and gutters from the committed source.

Snapshot undo may replace an unchanged code node with an equal node object while ProseMirror reuses its NodeView without updating React props. Publication therefore accepts structurally equal current nodes, while rejecting changed source or attributes. A replacement can also remove decorations without changing that NodeView at all. Syntax decorations record their owner; mapping reports only owners whose decorations were removed, and the plugin view asks those surviving visible owners to reinstall their cached token window after positions have updated. Controls recover their last visible window through the same targeted lifecycle. Recovery still waits for IME completion, does not walk the document, and does not request new tokenization for an unchanged mounted owner.

Long blocks also keep one semantically plain text chunk per 400 lines. These stable spans retain all editable source, including offscreen text, while preventing each viewport update from replacing one enormous plain text run in Chromium's accessibility tree. Only those cheap chunks survive offscreen; syntax spans and gutter widgets do not. A measured 10,000-line / 237,779-character JavaScript fixture rendered 54 gutters and 108 syntax spans at its bottom without focus. Chromium tracing reduced its initial accessibility commits from roughly 0.9 seconds to 0.4 seconds; scrolling decoration dispatches took 2–4 ms with no renderer long task above 50 ms during that scroll. Initial document/first-color accessibility work remains a measured cost, not a zero-latency guarantee.

Regression coverage lives in `codeVisibility.test.ts` (zero-height startup, scroll without intersection callbacks, unchanged-size hidden-tab restoration and shared scheduling), `codeVisibilityMount.test.tsx` (asynchronously inserted 10,000-line block scrolled to its final line without focus or a ready worker), `codeHighlightMount.test.tsx` (equal reused nodes, discarded decorations, repeated disclosure/slash-text/formula history restoration, and IME), and the folding/move suites. Browser acceptance must target the active, on-screen editor and wait for asynchronously loaded code blocks before scrolling; cached tab editors remain mounted offscreen.

CodeMirror and rich-document code fences share the `--hljs-*` roles, using hues from Winc's Day, Paper, and Night palettes on NoteBoard's existing backgrounds. Tags and keywords use brick or copper, properties and attributes use plum or pink, CSS selectors use blue, custom properties use olive or gold, and CSS named values use teal. Punctuation, comments and line numbers use subdued neutrals. The contrast tests read the shipped CSS and check every syntax foreground and both line-number surfaces against the 4.5:1 text threshold. [Winc theme source](https://github.com/DEEIX-AI/Winc/blob/d92e169e/crates/winc-app/src/theme/winc.rs)

CodeMirror and CSS fences use the same Lezer CSS grammar and tag-to-class mapping. The fence worker loads it on demand within the existing source and token budgets. Other fences and export retain Lowlight, including HTML's embedded languages, and HTML tag names, attributes and delimiters receive distinct foregrounds in both editors. Code, Mermaid and PlantUML language labels use neutral `--code-language-text`. Save pending/error feedback uses semantic foreground tokens for the titlebar and statusbar.
