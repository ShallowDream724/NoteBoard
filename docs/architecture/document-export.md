# 文档导出与编辑定位

## 所有权与模块边界

标题栏、Ctrl+E 和 Ctrl+P 打开同一导出入口。Ctrl+P 不调用浏览器页面打印。转换器、排版窗口和 PDF.js 按需加载。

- `editor-md/documentNodes.ts`、`documentExtensions.ts` 只定义文档结构、Markdown 语法及共享配置，不依赖 React、store、IPC 或 NodeView。编辑器的 `extensions/index.ts` 在同一语法上装配交互视图、历史与快捷键。
- `readDocumentSnapshot.ts` 从当前编辑器捕获权威快照：可视化模式取不可变节点的 JSON，源码模式取当前 CodeMirror 文本。导出不为此物化历史、更新镜像或保存文件；其他编辑器走能力接口的 `flush('export')`。
- `export/documentConversion.ts` 管理一次性 Worker。`documentWorker.ts` 在后台完成 JSON→Markdown、解析、KaTeX 和只读 HTML；关闭对话框立即终止 Worker。图片资源采用一次批量握手：Worker 保留生成的图片元素引用，主线程只将路径交给 `convertFileSrc` 并返回 URL，Worker 回填这些 `src` 后再做唯一一次 HTML 序列化；主线程不重新解析整份导出 DOM，也不猜测 Tauri URL 前缀。LinkeDOM 只在 Worker 内提供 DOM，并补齐浏览器对 HTML 片段的文档包装，保留原始 HTML 的解析语义。
- `renderDocument.ts` 输出包含公式、提示块 SVG、着色代码、图片和真实 thead 的独立 HTML，剔除交互控件。资源路径使用 `core/documentPath.ts`，生成后的资源重定位只更新图片 `src`，保留正文与代码中的 URI 文本。Pandoc 使用同一文档语法转成 JSON AST，公式是 Math 节点，不再次猜测货币定界符；表格列数采用共享稀疏逻辑网格，计入行列合并。

转换是 O(输入与输出大小) 的整体任务，公式的实际成本还取决于 TeX 复杂度。后台并不意味着零内存：转换期间会有文档树和 HTML。Worker 完成或取消即释放；临时公式缓存上限 4 MiB。编辑器 JSON 捕获本身仍是 O(节点数)，不建立逐字符映射或常驻第二份编辑器。

## 排版与逐项调整

默认 A4、12 mm 边距、10.5 pt 正文、1.4 行距。页码默认开启，可选位置与三种样式。页码所在边至少预留 8 mm，避免用户将边距设为零后与正文重叠。不会自行转为横向页面。

`createLayoutSession` 持有对象 ID 索引。整体纸张/字号变化重算所有对象；单项修改只恢复、调整该对象及所属表格。正文越界检查首次/全局调整时遍历全部正文，逐项调整只复查受影响的正文祖先，并保留其他块的已有越界结果；只为当前越界块保留引用，不建立第二份正文索引。集中读尺寸、集中写样式，避免逐对象强制整页布局。分栏复制只遍历输出需要的单元格，复杂度按输出大小增长；确定可以分栏后才序列化原表，只为当前已分栏的表格保留原始 HTML，恢复后释放。

- 默认“视觉最优”比较外层合法换行和适度缩放，已有 aligned 等结构不盲切。自动缩放按正文至少 8 pt、脚标等至少 6 pt、分数线等至少 0.25 pt 约束；这些是工程默认值，不是普遍适用的阅读标准。原始显式小字不会被算法擅自放大。
- `core/math/structure.ts` 保守读取 TeX 结构。支持分子、分母分别沿顶层加减项续行；不改变存储的公式。矩阵切分前按 TeX 语义消除注释及其换行，保留转义百分号，防止重组时注释吞掉后续单元格。独立矩阵按行列范围续排，各段标明索引；乘积中的矩阵、行列式/范数和无法识别的宏保持原式，可手动适宽或报告问题，不能声称支持任意 TeX 的语义改写。
- `mathLayout.ts` 每批最多 8 个矩阵段通过共享 Worker 渲染，再集中测量；采样只估计初始尺寸，每个实际候选段独立检查字号、线宽和允许缩放下限。完整矩阵或采样触发单式预算时仍走续排；候选段的 `limited` 结果在挂载 DOM 前二分重试，不冒充语法错误。无法继续分片的范围明确标记未完整显示并阻止默认导出。几何或可读性不符时也二分细化，最终恢复行列顺序。矩阵最多读取 250,000 个单元格，最多 4,096 段，累计生成标记预算 16 MiB；超限指出未完整显示的范围。预算针对展开后的显示结构，非仅按 Markdown 行数判断。
- 显式“缩到正文宽度”只按可用正文/单元格宽度等比缩小，没有最小字号下限，由用户判断阅读大小；内容保持文字与矢量，未转成截图。
- 宽表格由独立 `layoutPolicy.ts` 比较原字号、适度缩放与连续列组，重复首列并平衡末组空白；不强制占满正文。逐表可改为单表换行、分栏或适宽缩放。合并单元格暂不能分栏，仍可换行或适宽。
- 长表格按行跨页，重复表头；超过一页的单行允许续到下一页。没有按整张表高度缩小的选项。
- 手动列宽、最小行高和全文表格样式由共享 Markdown 语法保存，PDF 保留这些尺寸；按实测列宽续表，各组不强制填满正文。无法保留手动列宽时提示调整或适宽，不静默覆盖。详见 [表格尺寸与文档样式](table-presentation.md)。
- 左侧只列出需适配的对象（超宽、超高或渲染错误）。重复选择同一项目仍会定位；右侧点击续排片段不会跳回它的第一页。错误在两侧标红并带具体对象名，完整报错可复制。屏幕最多显示 100 个搜索结果。
- 正文、标题和行内代码允许长连续文本换行；排版后还检查普通文本块的实际横向边界。导出区域限制横向溢出，阻止 Chromium 因单个异常对象而把整份正文缩小。存在缺失/裁切时默认不导出；用户可明确勾选“仍按预览导出”。该选择绑定会话 ID 与 PDF 修订号，调整选项或重新建立会话后需重新确认。

## 原生会话、预览和资源释放

每次打开 PDF 预览建立一个 Rust 导出会话，拥有一个隐藏 WebView2、临时目录和顺序修订号。HTML 只发送并载入一次；原生侧交付载荷后释放该字符串。后续通过事件传入选项，不重建文档 DOM。

选项修改防抖 250 ms。生成中继续修改会合并到最新选项，不并行堆积打印窗口。新修订收到后暂停下一次打印，直到 PDF.js 首页面就绪并销毁旧读取任务才确认交接；保留修订号来自这次确认，不能提前按 receipt 更新。加载失败、原生错误、窗口关闭和取消都结束等待。关闭对话框会销毁排版窗口，后台 PDF 后处理在逐页边界检查取消，持有任务的后台工作结束后释放临时目录。文件保留当前输出、当前可见的旧修订，以及一份未加页码的 PDF，旧修订不能提前删除。

WebView2 `PrintToPdf` 负责完整分页。仅修改页码样式/位置且正文区域不变时复用原始 PDF，通过 lopdf 添加文字页码，不再调用浏览器分页。正文或纸张布局变化仍需重新生成完整 PDF；这不是增量分页引擎，不能声称一万页局部调整可毫秒完成。

`itemLocations.ts` 独立管理临时对象 URI 注释。公式在 KaTeX 不可分行的 `base` 或矩阵续排片段上添加无正文子节点的定位框，不用链接包住公式树，避免 Chromium 为每个内部字符产生注释；表格在边缘单元格使用独立定位锚点。生成后从真实 PDF 页提取边界，并删除内部链接，正文原有外链保留。重排只清理受影响对象的定位标记，不移动或重建数学正文。页码加入前隔离 Chromium 原内容的坐标变换，保证字号和位置正确。

排版窗口在挂载正文前应用目标纸张与字体变量，等待真实字体及图片就绪后开始计算，不添加固定延时。打印颜色在根节点统一继承，不在进入打印媒体时给每个后代应用通配规则，避免整篇数学 DOM 的无意义样式失效。列表项目禁止纵向 flex 压缩，内容超高时滚动；长标签省略并提供悬停全文。0.3.12 的分阶段测量见[打印预览耗时记录](../performance/0.3.12-打印预览.md)。

`PdfPreview` 使用 PDF.js RangeTransport 按需读取，单次 IPC 不超过 1 MiB，正常块为 64 KiB，不把整份 PDF 反复复制进 React。仅可见页面及前后一页有画布；新 PDF 就绪前保留旧代理和画布，交接后释放旧加载任务。保存将当前修订流式复制到目的目录临时文件，完成同步后原子替换用户目标；失败保留原文件，不额外整份读入内存。PDF 与 Pandoc 共用该临时文件提交模块。

## Pandoc

统一解析显式路径、PATH，以及 Windows LocalAppData/Program Files 下的 Pandoc 安装目录。“设置 → 导出”可指定路径；缺失时引导官方下载，不自动安装。先由 `begin_pandoc` 建立归属当前窗口的会话，再启动可取消的转换 Worker 和 `pandoc_export`。每窗口最多一个会话、全局最多四个；关闭对话框或宿主窗口会终止并回收子进程。转换时并发写 stdin 并持续读取输出，每路最多留存 1 MiB，避免管道等待与警告无限累积。程序检测限时 10 秒，转换限时 30 分钟。结果先写同目录临时文件，成功且未取消才原子替换目的文件；失败或取消保留原文件并清理临时结果。

DOCX 的最终分页由 Word/WPS 决定；PDF 逐项分页设置不强行映射为 DOCX 页面位置。HTML 使用 MathML；LaTeX 保留公式源码，后续编译需要本机 TeX 环境。外部格式不保证 PDF 的全部配色与排版。Mermaid/PlantUML/Infographic 在文档 PDF 中仍保留源码，图形导出尚未接入。

文本高亮在 Pandoc AST 中保留经共享规则检查的 `data-color` 与背景样式，HTML 保留该颜色。当前 Word/LaTeX 转换不映射高亮底色，含高亮的文档导出这些格式时返回可复制的简洁提示；不静默丢失，也不引入自写格式转换器。

## 编辑性能与位置同步

0.3.8 增加独立大矩阵的单元格窗口显示、长表布局隔离及大纲二分定位。矩阵源数据完整保留，编辑显示与 PDF 续排共用 `core/math/structure.ts`，各自拥有展示状态。适用范围、复杂度与仍存在的慢帧见[压力文档滚动记录](../performance/2026-09-22-压力文档滚动.md)。

`sourcePosition.ts` 为每个活 Editor 通过弱引用保留最新 doc + Markdown 的一份 token/块索引，内容或文档根变化即替换；已识别块用二分找到两个端点，仅对选中块展开语义映射。非规范源码走完整语义匹配回退。不在 store/history 保存全文 source map，不在滚动/光标路径更新索引。共享语法为每个所有者建立独立 Marked，避免规则随编辑器数量累加；列表首行守卫避免普通段落重复拆分剩余全文。

两模式采用保留布局的可见性切换，选区工具栏的 ProseMirror 插件保持注册，通过启用状态控制显示。公式用有界 Worker 批次生成 HTML；`mathPreview` 独立拥有预览宿主，DOM 挂载按估计节点成本调度。小文档主动预排，大文档准备上下两屏；仅驻留预算不足时回收非邻近内容，离屏本身不回收。共享 ResizeObserver 记录占位尺寸和行内基线。活动状态显式传入会话，隐藏时取消待办；公式结果缓存上限 4 MiB。代码高亮结果每帧合并为一个事务。详见[公式架构](markdown-math.md)。

公式的离屏判定按纵向窗口工作，横向浏览超宽内容不卸载公式；占位宽度同时包含溢出内容，避免横向滚动突然复位。表格源码使用紧凑 GFM，不再按最长单元格填充空格与分隔线。Ctrl+/ 仅由活动标签消费；代码块内 Ctrl+A 只选当前代码块。

当前 ProseMirror 并未实现整个文档虚拟化。超过 200,000 字符使用源码模式，不能强行进入完整可视化。已移除未接入且存在二次复杂度的旧分段原型；稳定的大文档可视化分页编辑属于后续独立工作。

## 验证与边界（2026-09-21）

2026-09-22 补充：千行、四列矩阵生成 23 页样本 PDF，逐一核对 4,000 个单元格及结尾；分子和分母各 40 项的分式均续行。70×12 手动列宽表的自动方案使用 85% 缩放及两组续表，所有 840 个单元格保留。单个超宽对象曾导致整份 10.5 pt 正文被 Chromium 压到 7 pt；限制横向溢出后保持 10.5 pt。Atlas 466 个公式快速往返滚动，最多挂载 29 个预览、无文档修改事务；该次开发浏览器帧间隔 p95 16.8 ms，无 50 ms 以上长任务。仍需安装版用户手感验收。

- 共享语法一致性、公式编辑/视口回收、序列化、历史、模式定位和导出等回归；实际 Worker 解析保留 HTML 强调和表格结构。
- `scripts/generate-export-fixture.mjs` 生成千行表、120×30 宽表及复杂公式。原生生成 64 页 PDF，逐项核对 1000 行及所有宽表单元格；表头、合并单元格、正文外链和结尾均保留，内部定位 URI 已删除。两次修订使用同一会话。
- 同一 64 页样本仅改页码位置/样式约 121 ms，实际 PDF 页码为 9 pt 并位于所选位置。本机非 PATH 安装的 Pandoc 3.2 已由标准目录发现；DOCX、HTML、LaTeX 实际转换完成，分别核对 OMML 数学对象、MathML 和公式源码。
- 10,000 页纯文本强制分页样本：原生生成约 28 秒，探针及 WebView 进程组私有内存峰值约 1,029 MiB。它验证大页数流程，不代表一万页复杂公式有相同时长或内存。
- 同一 9.7 MB PDF 的预览首次显示约 437 ms；跳到第 9500 页后只挂载 3 张画布，累计按需读取约 1.25 MB。预览按需绘制不等于 PDF 生成也按页增量。
- 完整编辑协调器的三份 100,000 行样本在开发版浏览器中约 0.40–0.45 秒进入源码，输入与末尾定位成功，DOM 164–200 个。Atlas 映射约 6 ms；连续滚动未记录到 50 ms 以上长任务。上述不替代用户机器上的最终交互验收。

真正的增量分页需要独立的分页模型、页级依赖和可拼接输出，不能靠重复 PrintToPdf 或 DOM 分段冒充。当前不发布 v1.0，待导出交互及上述边界验收后决定后续引擎工作。
