# 文档导出与编辑定位

## 所有权与模块边界

标题栏、Ctrl+E 和 Ctrl+P 打开同一导出入口。Ctrl+P 不调用浏览器页面打印。转换器、排版窗口和 PDF.js 按需加载。

标题栏导出按钮仅在当前标签是 Markdown 或 NoteBoard 文档时显示；欢迎页及其他文档类型隐藏该入口，快捷键沿用相同的文档类型守卫。导出弹窗内生成中或尚未满足导出条件时，提交按钮继续显示禁用状态。

信息图导出的 `react-dom/server` 也保持按需加载。Vite 将它的入口及 `react-dom-server*` 实现单独放入 `vendor-react-server`，首屏 `vendor-react` 只承载客户端运行时；不能因为同属 `react-dom` 就合并进首屏。构建来源清单记录具体服务端渲染模块，启动门禁按模块证据阻止其进入静态闭包，即使总字节仍低于预算也拒绝通过。

- `editor-md/documentNodes.ts`、`documentExtensions.ts` 只定义文档结构、Markdown 语法及共享配置，不依赖 React、store、IPC 或 NodeView。编辑器的 `extensions/index.ts` 在同一语法上装配交互视图、历史与快捷键。
- `readDocumentSnapshot.ts` 从当前编辑器捕获权威快照：可视化模式取不可变节点的 JSON，源码模式取当前 CodeMirror 文本。导出不为此物化历史、更新镜像或保存文件；其他编辑器走能力接口的 `flush('export')`。
- `export/documentConversion.ts` 管理一次性 Worker。`documentWorker.ts` 在后台完成文本投影、解析、KaTeX 和只读 HTML；关闭对话框立即终止 Worker。图片资源采用一次批量握手：Worker 保留生成的图片元素引用，主线程只将路径交给 `convertFileSrc` 并返回 URL。图表也按批次握手，由真实浏览器调用共享图表渲染器；Worker 等待图形回填后再做唯一一次 HTML 序列化。主线程不重新解析整份导出 DOM，也不猜测 Tauri URL 前缀。LinkeDOM 只在 Worker 内提供 DOM，并补齐浏览器对 HTML 片段的文档包装，保留原始 HTML 的解析语义。
- `renderDocument.ts` 输出包含公式、提示块 SVG、着色代码、图片和真实 thead 的独立 HTML，剔除交互控件。资源路径使用 `core/documentPath.ts`，生成后的资源重定位只更新图片 `src`，保留正文与代码中的 URI 文本。Pandoc 使用同一文档语法转成 JSON AST，公式是 Math 节点，不再次猜测货币定界符；表格列数采用共享稀疏逻辑网格，计入行列合并。

转换是 O(输入与输出大小) 的整体任务，公式的实际成本还取决于 TeX 复杂度。后台并不意味着零内存：转换期间会有文档树和 HTML。Worker 完成或取消即释放；临时公式缓存上限 4 MiB。编辑器 JSON 捕获本身仍是 O(节点数)，不建立逐字符映射或常驻第二份编辑器。

## 增强内容与独立 HTML

`richProjection.ts` 管理 Markdown、HTML 和打印的增强内容投影；Pandoc 由 `pandocDocument.ts` 直接遍历原始文档节点，不再先投影成便携内容或经 JSON 重建第二棵 ProseMirror 树。两条路径均只建立一次说明索引。未知节点与 `nativeError` 保留为普通代码块，后者使用 `attrs.raw` 原文；未知标记、缺失或循环说明引用明确报错。Markdown 使用标准表格保留图片组合中的图片、图注与空槽，说明编号附于文末。Pandoc 使用原生 Table 表示静态网格、Note 表示脚注、Math 表示公式，展开折叠标题与正文。PDF 同样保留完整网格，不依赖当前轮播页或已挂载表格行。

HTML 直接在一次性 Worker 中生成，不需要 Pandoc。`standaloneHtml.ts` 装配独立 CSS 与小型增强脚本；保留 details、模糊揭示及轮播，禁用脚本时图片全部可读。打印前展开内容，打印后恢复阅读状态。HTML 的本地图片使用原文档目录解析后的文件 URL，PDF 则继续使用 Tauri 资源握手。HTML 和 PDF 共用表格边缘标记与三线表样式。导出面板仅展示当前内容实际产生的降级摘要。

### 图表进入 HTML 与 PDF

`renderDocument.ts` 将 Mermaid、PlantUML、Infographic 节点收集成一次请求，保留元素位置，等待 `renderDiagrams.ts` 返回静态图形；正常图表不再统一替换成源码。Mermaid 必须使用浏览器的 SVG 尺寸测量，不能在 LinkeDOM 中伪造结果。`diagram-preview/mermaidRenderer.ts` 是编辑节点、图表分栏预览和导出的共同惰性加载/串行渲染边界，临时可测量容器在成功、失败和取消后释放，排队中的废弃任务可取消。PlantUML 复用原有在线服务与 LRU 缓存，导出请求可取消并设 20 秒超时；信息图复用原有解析器和 React 组件生成静态 HTML，不截图或重写一套图形生成器。

导出使用浅色图表；Mermaid/PlantUML 保留 SVG，信息图保留文字和 DOM 布局。打印排版在图表完成后开始，矢量图适应正文宽度与页高；文字缩小到难读时给出可定位提示，用户可明确选择适宽。只有渲染器实际失败才显示错误和保留的源码，错误不会伪装成已渲染图形。关闭导出会同时取消图表请求并释放 Worker。

2026-09-25 定向验收：通过实际 `prepareDocument → documentWorker → 共享渲染器 → createLayoutSession → Edge printToPDF` 生成一页样本，含 Mermaid 流程图、PlantUML 时序图和 Infographic 流程卡片；3 张图表、2 个直接 SVG、0 源码回退、0 排版问题。PDF 文本层包含全部图表标签，整页视觉检查无裁切，普通 JavaScript 代码仍按代码显示。该验证覆盖浏览器排版链路，不替代 Tauri 原生保存对话框生命周期验收。

此前 PDF 验收样本包含七张不同 PNG、空槽、仅图注槽、轮播、折叠、两种模糊、行内/块说明、说明内图片/列表/代码、数学和二十行表格。生产 Worker 经 Edge 153 打印的两份 PDF 各三页、七次图片绘制，全部十八个内容标记保留；六页渲染图无裁切和重叠。这项记录不替代后续 Pandoc 目标适配器验收，也不替代 Tauri 原生保存对话框生命周期测试。

## 排版与逐项调整

默认 A4、12 mm 边距、10.5 pt 正文、1.4 行距。页码默认开启，可选位置与三种样式。页码所在边至少预留 8 mm，避免用户将边距设为零后与正文重叠。不会自行转为横向页面。

`createLayoutSession` 持有对象 ID 索引。整体纸张/字号变化重算所有对象；单项修改只恢复、调整该对象及所属表格。正文越界检查首次/全局调整时遍历全部正文，逐项调整只复查受影响的正文祖先，并保留其他块的已有越界结果；只为当前越界块保留引用，不建立第二份正文索引。集中读尺寸、集中写样式，避免逐对象强制整页布局。分栏复制只遍历输出需要的单元格，复杂度按输出大小增长；确定可以分栏后才序列化原表，只为当前已分栏的表格保留原始 HTML，恢复后释放。

- 默认“视觉最优”比较外层合法换行和适度缩放，已有 aligned 等结构不盲切。自动缩放按正文至少 8 pt、脚标等至少 6 pt、分数线等至少 0.25 pt 约束；这些是工程默认值，不是普遍适用的阅读标准。原始显式小字不会被算法擅自放大。
- `core/math/structure.ts` 保守读取 TeX 结构。支持分子、分母分别沿顶层加减项续行；不改变存储的公式。矩阵切分前按 TeX 语义消除注释及其换行，保留转义百分号，防止重组时注释吞掉后续单元格。独立矩阵按行列范围续排，各段标明索引；乘积中的矩阵、行列式/范数和无法识别的宏保持原式，可手动适宽或报告问题，不能声称支持任意 TeX 的语义改写。
- `mathLayout.ts` 每批最多 8 个矩阵段通过共享 Worker 渲染，再集中测量；采样只估计初始尺寸，每个实际候选段独立检查字号、线宽和允许缩放下限。完整矩阵或采样触发单式预算时仍走续排；候选段的 `limited` 结果在挂载 DOM 前二分重试，不冒充语法错误。无法继续分片的范围明确标记未完整显示并阻止默认导出。几何或可读性不符时也二分细化，最终恢复行列顺序。矩阵最多读取 250,000 个单元格，最多 4,096 段，累计生成标记预算 16 MiB；超限指出未完整显示的范围。预算针对展开后的显示结构，非仅按 Markdown 行数判断。
- 显式“缩到正文宽度”只按可用正文/单元格宽度等比缩小，没有最小字号下限，由用户判断阅读大小；内容保持文字与矢量，未转成截图。
- 宽表格由独立 `layoutPolicy.ts` 比较原字号、适度缩放与连续列组，重复首列并平衡末组空白；不强制占满正文。逐表可改为单表换行、分栏或适宽缩放。合并单元格暂不能分栏，仍可换行或适宽。
- 长表格按行跨页，重复表头；超过一页的单行允许续到下一页。没有按整张表高度缩小的选项。
- 手动列宽、最小行高和全文表格样式由共享 Markdown 语法保存，PDF 保留这些尺寸；按实测列宽续表，各组不强制填满正文。无法保留手动列宽时提示调整或适宽，不静默覆盖。详见 [表格尺寸与文档样式](table-presentation.md)。
- 左侧只列出需适配的对象（超宽、超高或渲染错误）。重复选择同一项目仍会定位；右侧点击续排片段不会跳回它的第一页。错误在两侧标红并带具体对象名，完整报错可复制。屏幕最多显示 100 个搜索结果。
- 正文、标题和行内代码允许长连续文本换行；排版后还检查普通文本块的实际横向边界。导出区域限制横向溢出，阻止 Chromium 因单个异常对象而把整份正文缩小。存在缺失/裁切时默认不导出；用户可明确勾选“仍按预览导出”。该选择绑定会话 ID 与 PDF 修订号，调整选项或重新建立会话后需重新确认。

## 原生会话、预览和资源释放

每次打开 PDF 预览建立一个 Rust 导出会话，拥有一个隐藏 WebView2、临时目录和顺序修订号。HTML 只发送并载入一次；原生侧交付载荷后释放该字符串。后续通过事件传入选项，不重建文档 DOM。

选项修改防抖 250 ms。生成中继续修改会合并到最新选项，不并行堆积打印窗口。新修订收到后暂停下一次打印，直到 PDF.js 首页面就绪并销毁旧读取任务才确认交接；保留修订号来自这次确认，不能提前按 receipt 更新。加载失败、原生错误、窗口关闭和取消都结束等待。关闭对话框会销毁排版窗口，后台 PDF 后处理在逐页边界检查取消，持有任务的后台工作结束后释放临时目录。文件保留当前输出、当前可见的旧修订，以及一份未加页码的 PDF，旧修订不能提前删除。

WebView2 `PrintToPdf` 负责完整分页。仅修改页码样式/位置且正文区域不变时复用原始 PDF，通过 lopdf 添加文字页码，不再调用浏览器分页。正文或纸张布局变化仍需重新生成完整 PDF；这不是增量分页引擎，不能声称一万页局部调整可毫秒完成。

`itemLocations.ts` 独立管理临时对象 URI 注释。公式在 KaTeX 不可分行的 `base` 或矩阵续排片段上添加无正文子节点的定位框，不用链接包住公式树，避免 Chromium 为每个内部字符产生注释；表格在边缘单元格使用独立定位锚点。生成后从真实 PDF 页提取边界，并删除内部链接，正文原有外链保留。重排只清理受影响对象的定位标记，不移动或重建数学正文。页码加入前隔离 Chromium 原内容的坐标变换，保证字号和位置正确。

排版窗口在挂载正文前应用目标纸张与字体变量，等待真实字体及图片就绪后开始计算，不添加固定延时。打印颜色在根节点统一继承，不在进入打印媒体时给每个后代应用通配规则，避免整篇数学 DOM 的无意义样式失效。列表项目禁止纵向 flex 压缩，内容超高时滚动；长标签省略并提供悬停全文。0.3.12 的分阶段测量见[打印预览耗时记录](../performance/0.3.12-打印预览.md)。

`PdfPreview` 使用 PDF.js RangeTransport 按需读取，单次 IPC 不超过 1 MiB，正常块为 64 KiB，不把整份 PDF 反复复制进 React。仅可见页面及前后一页有画布；新 PDF 就绪前保留旧代理和画布，交接后释放旧加载任务。保存将当前修订流式复制到目的目录临时文件，完成同步后原子替换用户目标；失败保留原文件，不额外整份读入内存。PDF 与 Pandoc 共用该临时文件提交模块。

导出弹窗打开期间，应用主编辑区设为 `inert`，避免延迟编辑器 focus 抢回焦点、显示正文光标或接收编辑输入。初始焦点落在弹窗容器，不自动落在格式选择框；关闭后恢复原焦点。PDF 预览是可聚焦的原生滚动区域，单击页面或在页面滚动会将焦点留在预览内，修正从设置输入框切回页面时的焦点归属。滚轮不拦截默认行为、不换算 delta、不调用自定义滚动动画；触控板的像素滚动和惯性由浏览器保留。焦点交接使用 `preventScroll`，不改变虚拟页面位置；只有显式点击内容定位入口才跳转页面。

打印继承主窗口的中西文字体链和代码字体链；字体包的 `@font-face` 在独立打印 WebView 中重新声明，经 asset 协议加载，并不依赖安装到 Windows。`waitForExportFonts` 先让新正文参与一次布局以触发实际用到的字体加载，再等待 FontFaceSet；避免冷缓存下取到插入正文前已经完成的 `fonts.ready`。仅加载正文实际使用的字重，不预加载整个字体包。加载失败的已用字体明确报错，不静默输出替代字体。用户选择的本机字体由同一字体链交给 WebView2；默认系统回退仅用于没有配置或缺字的字符。

表格临时排版保存原列组和表格样式的小型快照，切换打印模式先恢复基线；显式“单表换行”可覆盖手动列宽，但不改文档。逻辑列宽从直接 colgroup 获取，避免把合并表头当作单列或读到嵌套表格。超高行先集中读取几何并创建离线续行，最后统一替换，避免每处理一行都触发整表重排；仍按实际输出规模付出克隆成本。

## 预览等待反馈

`ExportProgress` 是独立显示组件。首次生成居中显示进度圈，阶段文字位于圈内；更新时保留已有 PDF，右上角使用同一组件的紧凑形式。文字对应实际工作：整理文档、准备预览、启动排版、加载字体与图片、内容排版、生成 PDF、处理页码与链接、加载预览。只显示已用时间，不以定时器模拟完成比例或固定倒计时。

`usePdfJob` 在请求原生任务前建立事件订阅；原生 `pdf-progress` 只在阶段边界发送到任务拥有者，携带会话 ID 和修订号。隐藏窗口通过受窗口身份约束的 `pdf_layout_started` 报告开始排版；资源、打印、后处理由原生任务的真实边界报告。主窗口忽略其他会话、旧修订和倒退阶段；关闭时释放订阅，订阅尚未建立时关闭也不会随后启动任务。进度通知失败不阻止 PDF 生成。错误、取消和预览读取交接沿用现有任务生命周期，不新增轮询或每页通知。

圈使用 CSS `transform` 旋转；一秒一次的计时只更新显示组件，不更新弹窗或 PDF 画布。阶段通过 `role=status` 宣告，秒数不重复播报；减少动态效果时停止旋转，继续显示阶段和时间。短阶段不人为停留。此界面反馈不改变前述全文分页成本，也不额外保存文档或常驻估算缓存。

## Pandoc

统一解析显式路径、PATH，以及 Windows LocalAppData/Program Files 下的 Pandoc 安装目录。“设置 → 导出”可指定路径；缺失时引导官方下载，不自动安装。先由 `begin_pandoc` 建立归属当前窗口的会话，再启动可取消的转换 Worker 和 `pandoc_export`。每窗口最多一个会话、全局最多四个；关闭对话框或宿主窗口会终止并回收子进程。转换时并发写 stdin 并持续读取输出，每路最多留存 1 MiB，避免管道等待与警告无限累积。程序检测限时 10 秒，转换限时 30 分钟。结果先写同目录临时文件，成功且未取消才原子替换目的文件；失败或取消保留原文件并清理临时结果。

DOCX 的最终分页由 Word/WPS 决定；PDF 逐项分页设置不强行映射为 DOCX 页面位置。HTML 使用 MathML；LaTeX 保留公式源码，后续编译需要本机 TeX 环境。外部格式不保证 PDF 的全部配色与排版。Mermaid/PlantUML/Infographic 在 HTML/PDF 中输出图形；当前 Pandoc 的 Word/LaTeX 目标继续以代码块保留图表源码。

Word/LaTeX 要求 Pandoc 3.0 或更新版本。Rust 读取当前可执行程序的 API 版本，拒绝旧 Table AST，再为该次任务创建内嵌 `pandoc-targets.lua` 的临时副本；临时资源随任务释放。目标 writer 调用 Pandoc 自身 writer，不重新实现图片关系、公式、列表、表格或脚注序列化。

- AST 的 `nb-color/background/align/indent/vertical` 是两个目标共享的有限展示词汇，目标输出不以 CSS 属性代替真实样式。图片尺寸使用 Pandoc 标准 `width`/`height` 属性；表格以稀疏逻辑网格计算列宽比例和行列合并。
- DOCX 使用去重的命名字符、段落和表格样式；颜色/高亮写入 `w:rPr`，对齐/缩进写入 `w:pPr`，带展示属性的标题继承对应 Heading 样式。Pandoc 完成文档后，内嵌 ZIP API 替换生成样式；单元格属性通过带嵌套栈的 XML 扫描写入各自 `w:tcPr`，临时标记全部移除。正文、脚注内表格都适用，避免按表格序号或 XML 字符串相邻关系猜测归属。
- LaTeX 采用 `xcolor` 的文字颜色和高亮命令、对齐环境、`changepage` 缩进环境、`colortbl` 单元格底色，保留 Pandoc 的列宽、合并、图片和脚注命令。单元格垂直对齐仍由 TeX 排版决定，遇到非顶对齐时明确提示；高亮使用不可拆分的颜色盒，长高亮范围可能需要用户在 TeX 排版中调整。导入的其他 CSS 色彩空间若不能转换，明确提示并保留正文。Word/WPS 视觉分页及 TeX 编译不由结构回归测试担保。

`test/export/pandocTargets.test.ts` 发现本机配置或标准目录下的 Pandoc 后执行真实目标转换，读取 DOCX ZIP 中的样式/正文/脚注 XML，并核对 LaTeX 目标命令。测试覆盖共享样式、标题/段落对齐、缩进、图片尺寸、表格列宽与行列合并、单元格属性、说明公式及展开内容；缺少可执行程序时跳过该集成测试，普通 AST/内容守恒回归仍执行。相关接口依据 [Pandoc 自定义样式](https://pandoc.org/MANUAL.html#custom-styles)、[图片尺寸](https://pandoc.org/MANUAL.html#images) 和 [Lua API](https://pandoc.org/lua-filters.html)。

关联 Markdown 保存传递 `prepareTextExport(..., 'noteboard')` 的显式输入格式，在一次性 Worker 内解码 NB、重定位资源并生成干净 Markdown；不在主线程先解码整棵树再结构化克隆，也不根据字符串内容猜测文件格式。

## 编辑性能与位置同步

0.3.8 增加独立大矩阵的单元格窗口显示、长表布局隔离及大纲二分定位。矩阵源数据完整保留，编辑显示与 PDF 续排共用 `core/math/structure.ts`，各自拥有展示状态。适用范围、复杂度与仍存在的慢帧见[压力文档滚动记录](../performance/2026-09-22-压力文档滚动.md)。

`sourcePosition.ts` 为每个活 Editor 通过弱引用保留最新 doc + Markdown 的一份 token/块索引，内容或文档根变化即替换；已识别块用二分找到两个端点，仅对选中块展开语义映射。非规范源码走完整语义匹配回退。不在 store/history 保存全文 source map，不在滚动/光标路径更新索引。共享语法为每个所有者建立独立 Marked，避免规则随编辑器数量累加；列表首行守卫避免普通段落重复拆分剩余全文。

两模式采用保留布局的可见性切换，选区工具栏的 ProseMirror 插件保持注册，通过启用状态控制显示。公式用有界 Worker 批次生成 HTML；`mathPreview` 独立拥有预览宿主，DOM 挂载按估计节点成本调度。小文档主动预排，大文档准备上下两屏；仅驻留预算不足时回收非邻近内容，离屏本身不回收。共享 ResizeObserver 记录占位尺寸和行内基线。活动状态显式传入会话，隐藏时取消待办；公式结果缓存上限 4 MiB。代码高亮结果每帧合并为一个事务。详见[公式架构](markdown-math.md)。

公式的离屏判定按纵向窗口工作，横向浏览超宽内容不卸载公式；占位宽度同时包含溢出内容，避免横向滚动突然复位。表格源码使用紧凑 GFM，不再按最长单元格填充空格与分隔线。Ctrl+/ 仅由活动标签消费；代码块内 Ctrl+A 只选当前代码块。

当前 ProseMirror 并未实现整篇文档虚拟化。大型无合并表格已支持按视口挂载单元格，见 [编辑器性能](editor-performance.md)。Markdown 超过可视化阈值时使用源码模式；NB 源码模式编辑自身格式，导出通过显式输入格式在 Worker 中解析，不将 NB 源码当作 Markdown 正文。

- 共享语法一致性、公式编辑/视口回收、序列化、历史、模式定位和导出等回归；实际 Worker 解析保留 HTML 强调和表格结构。
- `scripts/generate-export-fixture.mjs` 生成千行表、120×30 宽表及复杂公式。原生生成 64 页 PDF，逐项核对 1000 行及所有宽表单元格；表头、合并单元格、正文外链和结尾均保留，内部定位 URI 已删除。两次修订使用同一会话。

- 10,000 页纯文本强制分页样本：原生生成约 28 秒，探针及 WebView 进程组私有内存峰值约 1,029 MiB。它验证大页数流程，不代表一万页复杂公式有相同时长或内存。

真正的增量分页需要独立的分页模型、页级依赖和可拼接输出，不能靠重复 PrintToPdf 或 DOM 分段替代。当前 PDF 生成仍采用完整文档排版；后续引擎演进需按实际分页与内存瓶颈单独评估。
