# NB、Markdown 与保存语义决策

记录日期：2026-09-25。本文记录已明确的产品要求与实现约束。当前实现说明见 [native-documents.md](native-documents.md)。磁盘语法现采用独立帧语义 JSON，编写规范见 [native-authoring.md](native-authoring.md)。

## 产品与格式边界

- 产品以 Markdown 兼容、可由 AI 编写的 NB、长期笔记管理和高质量 PDF 为核心。
- 新建默认 NB。Markdown 保留普通编辑及自身源码模式；不主动写入 NoteBoard 私有样式注释或私有 HTML 协议。
- 颜色、高亮、字号、任意段落对齐、合并单元格、精确表格尺寸、图片组合、说明等需要持久保存的增强功能，统一由格式能力定义判定是否需要 NB。
- 在 MD 中调用 NB 专属功能，先完成格式转换确认，成功后执行原操作；取消则不应用该操作。禁止出现已应用却无处保存的隐形富状态。
- 读取、保留已有 Markdown/HTML 与主动新增私有样式是不同能力。不能因模式切换擅自删除输入文件中的已有内容。
- 设置提供纯 Markdown 使用偏好：新建默认 MD、隐藏 NB 专属功能入口；不新建另一套编辑器，也不限制 Markdown 的阅读与 PDF 输出。
- HTML、Word、Excel 和图片粘贴共用导入模型和格式能力判定。MD 可表达的内容直接进入 MD；无法表达的增强先走 NB 转换，或由用户选择按 Markdown/纯文本降级粘贴。
- PDF 从完整文档模型输出。Word/LaTeX 按目标能力投影到 Pandoc，不能先统一退化为便携 Markdown。通用 Markdown 是独立导出目标。
- 提示块统一沿用 `githubAlert`。GFM 五种预设仍属于 MD；自定义/隐藏标题、图标和颜色属于 `callout` 原生能力。通用插入和块转换默认显示 Note 标题与图标，用户可明确隐藏标题；已有文档的隐藏标题保持原样。所有正文保持同一缩进，不从正文猜标题。随机配色只更新背景字段，显式背景的自动对比文字色只计算展示值；行内文字颜色优先。

## 转换、关联与文件树

MD 转 NB 的默认行为：在原文件所在目录创建同名 NB，并关联原来的 MD。两个文件在磁盘上并列保存，不创建包裹文件夹。弹窗复选项默认不勾选：

> 删除原 Markdown，不再关联

只有明确勾选时才移除原 MD；必须在 NB 成功写入后处理，并提供恢复保障。目标同名 NB 已存在时不得静默覆盖。

- 新建 NB 不自动创建 MD。
- 关联信息属于 NB 文档元数据：至少有目标路径、最后一致版本的校验信息、投影规则版本。优先使用可重定位的相对路径，不复制完整 Markdown 正文进元数据。
- 导出 Markdown 只放在导出入口，不增加独立常驻导出按钮。
- “更新关联 Markdown”只在当前 NB 确有 Markdown 关联时出现；来源于 MD 的新 NB 和重新打开的关联 NB 都适用。
- 文件树中 NB 使用统一、突出的专属图标；其关联 MD 缩进显示在下面。不能再在同一视图里显示第二个重复 MD 条目。
- 转换成功后主动刷新所在目录，定位 NB 并展开关联 MD，保留同一工作目录内其他已展开分支；不能只等待文件监听通知。若用户已切换标签或目录，过期定位不得把界面拉回。文件树刷新失败不撤销已完成的转换，应告知已保存路径。
- 关联索引允许缓存，但缓存不是文档内容的权威来源；不得在悬停、滚动或每次渲染时重新读盘解析整个 NB。
- 关联缺失、路径变更和多个 NB 指向同一 MD 必须明确处理，不能靠同名搜索自动选择更新目标。

## 保存、暂存与关闭

关闭沿用保存、不保存、暂存，不增加“只保存 NB”“只更新 MD”等变体。

| 操作 | 无关联文档 | 有关联的 NB |
| --- | --- | --- |
| 保存 | 保存当前文件 | 保存 NB，并把同一版本投影写入关联 MD |
| 不保存 | 放弃尚未提交的编辑 | 不再写入 NB 或 MD，放弃尚未提交的编辑 |
| 暂存 | 写入应用内部恢复区 | 暂存完整编辑快照、关联基准及资源引用，不写用户 NB/MD |

手动“更新关联 Markdown”复用同一成对保存服务；若有尚未保存的 NB 编辑，一并保存该版本，不单独提交派生结果。具体模块、事务与资源边界见 [原生保存架构](native-persistence.md)。

“不保存”不撤回此前已经完成的保存/手动更新，也不撤回其他软件写入的内容。恢复暂存时重新检查外部文件版本，不能用过期快照静默覆盖。

提交约束：

1. 捕获一个不可变版本，NB 和 MD 必须来自同一版本。
2. 先生成并验证待写结果，再提交；只有两份都完成才能显示保存成功。
3. 两个路径无法由单次文件替换共同提交。使用临时结果、版本校验和可恢复的提交记录处理部分成功及崩溃，不能把两次替换称为文件系统原子事务。
4. 转换、写入失败时保留编辑快照和原文件恢复能力；不能关闭并丢弃唯一的未保存内容。
5. 手动更新和关闭保存共用任务队列，合并重复请求；较旧任务完成不能覆盖较新编辑的脏状态。
6. 暂存中的新图片由应用恢复区持有，不复制进每次历史快照；资源发布与回收遵循实际引用和提交状态。

## 外部 Markdown 改动

要求：能可靠保留正文和 NB 样式的改动自动合回 NB；会导致样式失效、结构降级或存在歧义时才提示。不得把降级投影当作完整 NB 的可逆源码。

实现边界：

- 基于最后一致版本识别变更，区分外部 MD 修改、NB 未提交修改，以及两边同时变化。
- 有可靠基准时，对唯一对应的块及可明确定位的局部编辑使用编辑事务，保留未修改的样式和结构；自动导入也进入撤销链。
- 复杂表格变化、重复块的歧义对应、引用目标消失或共同基准缺失时，不进行不可靠的自动替换；保留双方内容，集中提示受影响部分。
- 优先采用顺序扫描、块摘要索引和有界局部比较。不得无条件做全文模糊匹配或无预算的全局差分。复杂度或资源预算超限时保留待处理状态，不冻结界面。
- 能由最后一致 NB 重建的基准不再常驻一份完整 MD；无法重建时不得伪造基准。必要的恢复缓存与用户目录中的第二份正文区分管理。
- 未解析内容、链接冲突和外部变化不能在保存时被静默吞掉。

## 源码与局部容错

- MD 提供自身源码模式；NB 普通写作只提供可视化编辑。NB 原始记录仅由错误块的显式修复入口打开，支持返回文档和统一历史，不跟随旧会话的源码首选。NB 不提供可编辑的派生 Markdown 源码。
- 源码错误不得被视觉模型的旧版本静默覆盖。保留原始错误片段及位置；可独立恢复的其他块正常渲染。
- 错误块显示局部、可定位到源码的诊断，不能整页空白，也不能让保存悄悄删除坏块。
- 文档头或分块边界严重损坏时，只恢复能可靠界定的内容；不能承诺任意坏文件都能完整解析。
- 缺图保留原图片节点与位置，显示缺失状态；轮播中的坏图片只影响该槽，页数、顺序和其他图片不变。
- HTML/Word/Excel 导入也使用相同的节点、资源、校验和诊断规则。
- 未知或无法解析内容必须有保留原文的路径。导出时不能跳过：能以标准代码块保留原文的，作为明确降级处理；无法可靠保存内容的，不能误报成功。

## 磁盘协议与性能

选用 `#!noteboard 1` + `@meta`/`@block`/`@child` 的独立帧语义 JSON：每条记录可单独解析，表格按行分片，坏记录在下一条 `@block` 可靠同步，省去完整 XML 解析器与宏展开。公共节点类型独立于编辑器，同时保留相近形状以减少树转换。此选择基于错误隔离、人工/AI 编写和实现边界；不把语法名称当作性能结论，仍需考察实际分配、缓存和峰值内存。

已确定的架构约束：

- 公开语义独立于编辑器内部字段，默认值可省略，供持久化、工具生成与互操作使用；不要求用户手写原始记录来完成可视化操作。
- 文档应有可靠、可独立识别的块边界，以支持局部校验、错误隔离及增量解析；块内部的大表仍需要适当粒度，不能把一万行全当一个不可分割的编辑单元。
- 全文打开和完整写出允许线性成本；普通输入不全文编解码，视图更新不遍历全部节点，不常驻重复 DOM/文档树。
- 样式随节点和范围事务更新；共同样式、列定义、行高默认值不在每个字符或单元格上重复保存。
- 附件按引用管理，避免大体积 Base64 混入全文快照；缓存有生命周期和内存边界。
- 若采用宏，只允许受控、可静态解析的样式/结构复用，不引入任意执行或不受限递归展开。
- 错误恢复有明确同步边界；单个遗漏闭合符不能无界吞掉后文。无法判定的区域保留原文。

当前按不可变块/行 WeakMap 缓存序列化，原生源码每键只捕获 Text 引用。全文打开/保存为线性工作；单个巨大单元格或嵌套容器仍可能形成较大记录，可重建索引与更细分片是后续根据实测决定的扩展。没有引入随机节点身份、宏或完整第二文档树。

## 统一能力定义

同一份能力描述供工具栏/粘贴、纯 MD 偏好、格式转换、保存检查及各目标导出使用。UI 不按文件后缀散落判断，保存层不猜测某个按钮会产生什么数据。

每个能力至少声明：MD 的表达方式或 NB 要求、NB 数据语义、编辑事务、资源依赖、PDF 表示、Pandoc 目标适配、通用 Markdown 降级及必要诊断。该能力表也作为 AI 编写规范的依据。
