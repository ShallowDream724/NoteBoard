# 图片与轮播交互

轮播的页码、滚动位置和图片预览缩放属于视图状态，不写入文档，也不进入撤销历史。

`rich-content/views.ts` 使用保留所有槽位的横向原生滚动视口与 CSS scroll snap。箭头和分页点调用可被后续输入打断的平滑滚动；触控板横向滚动使用浏览器的惯性与对齐。切换只更新页码控件、邻页加载提示和滚动位置，不通过 `display:none` 替换图片，不替换编辑器或文档内容。图片展示区保持固定比例，图注参与稳定的轨道高度计算。

活动图片与前后一张由 `imageVisibility.ts` 预先加载。离开的槽位释放预加载提示，其余图片继续共享视口观察器，避免为长轮播同时解码所有图片。缩小窗口后重新对齐当前页。减少动态效果偏好使用即时定位，控件保留明确的选中状态。

分页按钮用 `aria-pressed` 表达当前页，不在可编辑文档内创建 live region。模态框为保留 live region 而逐块改变 `aria-hidden` 会触发 ProseMirror 的 DOM 重解析，导致轮播视图状态丢失。

图片 `alt` 保留为辅助描述与加载失败时的替代文本，不自动复制为可见的灰色标题。图片悬停工具栏的“编辑图片描述”可修改或清空它；对话框等待期间图片位置会随事务映射，图片被删除或替换后不再提交。图片槽位中的图注仍是可编辑段落，可清空其文字。

全屏预览和独立图片查看器共用 `imageWheelGesture.ts`。通过非被动的原生 wheel 监听器接管 Chromium 的 `ctrl+wheel` 捏合事件，以连续缩放量围绕指针位置缩放图片，并阻止整个 WebView 跟随缩放。手势期间不叠加 CSS 过渡；预览放大后，普通触控板滚动可平移图片。缩放边界不改变锚点位置。
