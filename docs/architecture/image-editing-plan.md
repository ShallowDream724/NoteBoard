# 图片编辑与内存边界

状态：2026-09-27，方案已确定；图片编辑器尚未实现。本轮只修复图片粘贴、预加载与复制缓冲的生命周期。

## 统一入口与职责

普通图片、宫格和轮播共用图片节点与编辑入口。宫格只管理排列与槽位，不能分别维护三套编辑功能。现有“编辑图片描述”编辑的是 alt 文本（辅助阅读和加载失败的替代文字），不编辑像素，因此撤下主工具栏中的误导入口；文件中的 alt 元数据保留。

编辑 UI 按需加载，关闭后销毁整个编辑会话。先复用应用现有配色、文件资产、缩放平移和指针工具；不为图片编辑直接挂载整个画板运行时。工具状态、绘制操作、渲染器、资产写入分别封装，文档只持有图片资产引用及必要元数据。

## 功能与历史

第一阶段包含裁剪（自由/固定比例）、旋转/翻转、铅笔/荧光笔、直线/折线/单双箭头、矩形/椭圆、文字和马赛克。颜色、粗细、实虚线、箭头端点、文字粗体/斜体属于统一样式模型。

后续同一操作模型增加自动序号（数字、罗马数字、字母及可改起点）、实心/空心/双层圆与方形标记、聚光灯、放大镜、对象橡皮擦与笔迹擦除。序号递增由编辑会话管理，撤销恢复序号状态。

原图保持不变；裁剪、变换和矢量笔迹保存为有版本号的操作记录。撤销记录参数变化，不为每一步复制整张位图；需要像素处理的效果按区域记录。保存时生成新图片资产，再以一个文档事务替换引用，撤销可回到原图。取消不修改文档；导出失败不替换原图。

## 资源预算

只允许一个活动图片编辑会话。预览使用与显示尺寸匹配的工作图，原始像素仅在细节查看/导出时按需读取；高分辨率输出采用分块处理，控制同时在途任务。缓存按字节而非图片数量设限，超限淘汰可重新生成的预览。关闭、取消、失败及资源替换均释放临时 URL、位图、画布和 Worker 任务。

完整复制/导出保持原始分辨率，不能以降画质冒充优化。具体预览尺寸和字节限额需用大图样本定标，不能在尚未压测时承诺固定总内存上限。

## 当前性能证据和实施顺序

1. 轮播曾无条件预热当前页与邻页，即使整个轮播离开视野。本轮增加集合级视口门控，离开附近区域撤销邻页预热，继续共享一个 IntersectionObserver。
2. 图片查看器复制曾创建全尺寸画布且未主动释放。本轮复制串行化，PNG 编码完成即释放画布；成功与失败路径均回收。
3. 下一步建立原图到显示尺寸预览的缓存，重点减少多张大图的同时解码内存；缩放与导出仍使用原始资产。
4. 画板 `BoardEditor` 的 onChange 在防抖之前计算全场景签名和序列化，拖动会反复进行线性工作。应按 revision 合并快照，手势结束形成历史节点，保存边界再物化；保留撤销与暂存语义，需要独立回归后再交付。

2026-09-27 的隔离 rc.4 原生会话（用户主题/字体配置副本）中，示例顶部进程组私有工作集约 377 MiB，代码可见约 424 MiB；JS heap 约 19 MiB。它说明只看 JS heap 不足以解释总内存，不能当作本轮优化前后的对比，更不能据此宣布已减少 100 MiB。

验收使用相同 Release 构建条件、配置和样本，记录进程组私有工作集/Private Bytes、JS heap、同时解码图片数、Canvas 像素量、p95 帧时间和长任务。覆盖普通/大图、滚入滚出、连续编辑/撤销、导出/取消、重复打开关闭；同时验证小文档响应速度和功能不回退。
