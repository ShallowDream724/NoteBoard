# 图片编辑与内存边界

2026-09-27 已采用统一语义模型和按需加载的编辑器；具体接口、坐标、工具、导出格式及标签页草稿生命周期见 [图片编辑器](image-editor.md)。本文保留资源取舍和验收标准。

## 统一入口与职责

普通图片、宫格和轮播共用图片节点与编辑入口。宫格只管理排列与槽位，不能分别维护三套编辑功能。现有“编辑图片描述”编辑的是 alt 文本（辅助阅读和加载失败的替代文字），不编辑像素，因此撤下主工具栏中的误导入口；文件中的 alt 元数据保留。

编辑 UI 按需加载，活动界面销毁后释放位图与画布；暂停时保留轻量语义草稿，放弃或文档关闭时清除草稿。复用现有配色、文件资产和指针交互，不加载整个画板运行时。工具状态、绘制操作、渲染器、资产写入分别封装，文档只持有图片资产引用及必要元数据。

## 功能与历史

编辑器包含裁剪（自由/固定比例）、旋转/翻转、铅笔/荧光笔、直线/折线/单双箭头、矩形/椭圆、文字和马赛克。颜色、粗细、实虚线、箭头端点、文字粗体/斜体属于统一样式模型。

同一操作模型包含自动序号（数字、罗马数字、字母及可改起点）、实心/空心/双层圆与方形标记、聚光灯、放大镜、对象橡皮擦与笔迹擦除。序号递增由编辑会话管理，撤销恢复序号状态。

原图保持不变；裁剪、变换和矢量笔迹保存为有版本号的操作记录。撤销记录参数变化，不为每一步复制整张位图；需要像素处理的效果按区域记录。保存时生成新图片资产，再以一个文档事务替换引用，撤销可回到原图。取消不修改文档；导出失败不替换原图。

## 资源预算

只允许一个活动图片编辑界面。切换标签页暂停资源并保留草稿；恢复时核验来源、文档代次与图片身份。编辑预览长边默认最多 2048 像素，原图尺寸与坐标不变；首次浏览器解码仍可能短暂占用完整原图内存。导出在 Worker 中解码原图并编码，取消即终止 Worker。目前没有原图分块解码或流式编码；缓存预算不是进程内存硬上限。关闭、取消、失败及资源替换均释放临时 URL、位图、画布和 Worker 任务。

完整复制/默认导出保持原始分辨率，不能以降画质冒充优化。用户可主动选择 JPEG/WebP 质量与输出尺寸；Canvas 导出为 8 位结果，不保留源 10-bit/HDR、EXIF 或原色彩配置。预计像素内存超过 512 MiB 时先确认，设备能力允许可继续；实际画布和格式容量限制独立校验，不静默降采样。

## 当前性能证据和实施顺序

1. 轮播曾无条件预热当前页与邻页，即使整个轮播离开视野。本轮增加集合级视口门控，离开附近区域撤销邻页预热，继续共享一个 IntersectionObserver。
2. 图片查看器复制曾创建全尺寸画布且未主动释放。本轮复制串行化，PNG 编码完成即释放画布；成功与失败路径均回收。
3. 正文静态常规 8 位大图使用显示尺寸预览缓存，减少同时保留的解码像素。动画、HDR、特殊色彩配置及不确定格式保留原路径；复制、放大查看与编辑始终使用原图。
4. 画板 `BoardEditor` 保留必要的版本扫描，把全场景签名、序列化和历史物化合并到手势、空闲及保存边界，避免每个指针移动事件重复复制大场景；保存、撤销和暂存语义不变。

2026-09-27 的隔离 rc.4 原生会话（用户主题/字体配置副本）中，示例顶部进程组私有工作集约 377 MiB，代码可见约 424 MiB；JS heap 约 19 MiB。它说明只看 JS heap 不足以解释总内存，不能当作本轮优化前后的对比，更不能据此宣布已减少 100 MiB。

验收使用相同 Release 构建条件、配置和样本，记录进程组私有工作集/Private Bytes、JS heap、同时解码图片数、Canvas 像素量、p95 帧时间和长任务。覆盖普通/大图、滚入滚出、连续编辑/撤销、跨标签草稿、导出/取消、重复打开关闭；同时验证小文档响应速度和功能不回退。浏览器隔离数据不能等同整个 Tauri 应用的收益，不得使用强制换页来伪装常驻资源减少。
