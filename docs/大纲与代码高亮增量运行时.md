# 大纲与代码高亮运行时

## 文档导航布局

大纲是 `AppShell` 编辑区内的导航层，不再作为独立的右侧可调整面板。Markdown/原生文档的可视化滚动容器与 Markdown 源码的 CodeMirror 滚动容器始终占满编辑区，纵向滚动条保持在窗口右缘；正文内容层通过 CSS 变量给导航保留右侧空间。大纲从正文视口顶部下方 56px 开始，右侧保留 20–28px，底部至少留 40px；标题较多时只在导航列表内部滚动，滚动条在悬停或键盘焦点进入列表时显示。

布局根据编辑区容器宽度变化：720px 以内缩窄导航，560px 以内使用有边界的浮层并恢复正文全宽。收起大纲立即释放正文留白，编辑器宿主、内核、选区和撤销历史保持挂载。响应式布局只使用 CSS container query，不依赖窗口 resize 监听或全文几何测量；旧会话的 `outlineWidth` 字段保留兼容读取，导航宽度由容器决定。

## 大纲索引

`HeadingIndex` 属于当前挂载的大纲，初始化一次读取标题。后续按 ProseMirror 事务和附加事务映射已有标题位置，只重新提取修改范围。标题 ID 在同一索引的前文插入、标题改名和级别变化中保持稳定；删除/重新创建以及切换编辑器会重建对应身份。

普通光标位置的文本输入复用事务已经解析的选区路径，直接读取所在文本块，不调用整份文档的 `descendants` 或从开头跳过所有兄弟节点。每次文档变化仍有 O(H × M) 的标题位置映射与 O(H) 合并（H 为标题数，M 为事务映射数）。结构编辑需要读取实际变化子树；非选区位置的编辑还可能承担 ProseMirror 自身的兄弟节点定位成本。未知自定义步骤以及未连续收到事务时保守重建，不承诺常数时间。

大纲光标导航按文档位置二分。滚动导航由 `HeadingGeometry` 按编辑器顶层流块分组，结构或标题变化时建立标题 DOM 引用；存活的引用可以跨位置映射复用，只有新建或替换的标题需要 `nodeDOM` 定位。该定位在 ProseMirror 中可能线性扫描前面的块，因此只允许出现在结构重建中，不进入布局失效后的几何刷新。

滚动帧按各组**当前**的 viewport Y 二分，只在候选组内查询标题。单标题组直接读取标题位置，不注册尺寸依赖；多标题组缓存相对于所属块的 Y 并按 Y、文档位置排序，支持表格不同列内的非单调标题顺序。尺寸观察器仅使对应组失效，实际查询该组时才重新测量；标题祖先路径上的流兄弟也纳入依赖，覆盖短表格单元格变高但整行高度不变的情况。上方公式、图片等块变高只会整体移动后续组，不需要重新读取后续标题。

常规滚动需要 O(log G) 次块位置读取和 O(log K) 次组内二分；局部失效至多增加当前候选组的 O(K) 次标题几何读取与 O(K log K) 排序（G 为含标题的顶层块数，K 为组内标题数）。目标落在一个组首个标题之前时回查前组，空/隐藏标题组可能额外增加回查。结构重建为标题和流依赖的线性遍历，并承担新 DOM 的 ProseMirror 定位成本。结构观察器只观察编辑器根和标题祖先的直接子节点，不观察公式或矩阵 NodeView 的内部绘制；观察器与动画帧在面板清理时释放。

## 代码高亮

`codeHighlighting` 的主线程只管理请求、缓存和结果；lowlight 与语言语法在独立 Worker 中加载和分词。普通正文不会加载分词引擎。编辑器与导出共用纯分词和序列化模块；导出转换 Worker 直接调用纯引擎，不导入浏览器调度器或创建嵌套 Worker。

- 单个 Worker 同时处理一个请求；队列最多 64 个任务、估算源码内存最多 4 MiB。
- 相同语言与源码共享在途请求，消费者有独立 AbortSignal。最后一个消费者取消时删除排队任务；正在执行则终止 Worker，阻止旧源码继续占用 CPU。
- 结果 LRU 最多 256 项、估算 4 MiB，滚出视口再回来可复用。缓存估算包含源字符串、token 对象固定开销和样式字符串，不代表 JS 引擎精确堆占用。
- 单块最多 200,000 字符、16,384 个 token、估算 2 MiB token 数据；单次任务 5 秒 watchdog。越界、队列满、Worker 不可用或模块失败时保留纯文本，不在主线程补做同步分词。队列满的块在下一次请求时重试。
- Worker 空闲 30 秒后释放语法运行时；页面离开和开发热替换清空任务、结果缓存与 Worker。
- NodeView 的版本变化、离开附近视口及卸载会取消请求；结果发布前复核节点身份。装饰按帧合并，单帧预算约 4096 tokens，单个更大的块仍原子发布。发布时重新查询节点位置，避免前文编辑造成位置过期。其它 UI 注册插件时，ProseMirror 会重建所有 plugin view；高亮按 view 所有权区分这次重建与真正卸载，保留已经就绪的首批 token，真正卸载才清理未发布帧。

这些上限约束分词和驻留量，不代表大型代码块的 ProseMirror 装饰创建、DOM 更新或所有编辑器行为均为常数时间。
